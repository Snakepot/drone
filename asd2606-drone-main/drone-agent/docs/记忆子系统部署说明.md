# drone-agent 记忆子系统 部署说明

> 适用范围：启用了 `agent.memory.*` 的 `drone-agent`（`REQ-AGENT-0003`）。
> 决策背景见 [`../../docs/sdd/decisions/ADR-0003-引入记忆与服务端有状态.md`](../../docs/sdd/decisions/ADR-0003-引入记忆与服务端有状态.md)。

## 1. 四条硬性前提

这一版把 `drone-agent` 从「无状态」改成了「有状态」，部署方式因此多了几个**绕不过去**的要求：

| 前提 | 为什么 |
|---|---|
| **只允许 1 个实例** | 会话在进程内存里（Caffeine），长期记忆在本地文件。两个实例各存一份、互相覆盖，用户会看到「刚说的话一会儿记得一会儿不记得」。**不要给它配多副本或负载均衡。** |
| **`AGENT_MEMORY_ROOT` 必须挂卷** | 长期记忆是**永久保留**的，且是唯一副本。写在容器可写层里，容器一重建就全没了，且无法恢复。 |
| **固定时区（`TZ`）** | 正文按「会话开始日期」分片、索引里的时间都取 JVM 默认时区。容器不设 `TZ` 时默认 UTC，与运维习惯的日期对不上；**中途改 `TZ` 更麻烦**——同一天的数据会落到两个日期命名上。建议固定为 `Asia/Shanghai`。 |
| **目录可写且可追加** | 进程需要对根目录建目录、建文件、改名（原子重写用临时文件 + rename，见下）。只给读权限会直接启动失败。 |

> 单实例的取舍是**主动接受**的（ADR-0003），不是待办事项。要横向扩展必须回头改那条决策。

## 2. 配置项

`agent.memory.*` 全部在 `application.yml` 里，只有根目录支持环境变量覆盖：

| 配置项 | 环境变量 | 默认值 | 含义 |
|---|---|---|---|
| `agent.memory.root` | `AGENT_MEMORY_ROOT` | `./data/agent-memory` | 长期记忆根目录，**必须挂卷** |
| `agent.memory.session-max-count` | — | `500` | 内存中同时保留的会话数上限，超出时最久未访问的被归档后淘汰 |
| `agent.memory.idle-timeout` | — | `30m` | 会话空闲多久算结束；到期先归档再移除 |
| `agent.memory.max-messages-per-session` | — | `200` | 单会话在内存里的消息条数上限，超出则整体归档后移出 |
| `agent.memory.file-max-bytes` | — | `2MB` | 单个正文文件上限，超过则滚动到 `-2`、`-3`… |
| `agent.memory.inject-max-turns` | — | `10` | 注入模型的长期记忆轮数上限（**一轮 = 一问一答 = 2 条消息**） |
| `agent.memory.inject-max-chars` | — | `8000` | 注入模型的长期记忆字符数上限，超出从最早处截断 |

另有两个**必须与 `drone-server` 一致**的环境变量，配错的表现是「明明登录了却一直 401」：

- `JWT_SECRET`：两个服务必须填同一个值
- `DRONE_INTERNAL_TOKEN`：两服务之间的共享密钥，两边必须一致
- `DRONE_SERVER_URL`：本服务调 `drone-server` 内部接口的地址（默认 `http://localhost:8080`）

## 3. 数据目录长什么样

```
<AGENT_MEMORY_ROOT>/
├── audit.log                       # 删除审计，一行一条，只追加
└── <userId>/                       # 一个用户一个目录
    ├── memory.md                   # 该用户的索引，一行一个会话
    └── memory-2026-10-13.md        # 正文，按日期分片
        memory-2026-10-13-2.md      # 超过 2MB 后的第 2 个分片
```

**关于写入的原子性**：删除会话会过滤后整体重写文件，走「先写 `.tmp` 再 rename」，
所以中途被打断**不会**留下半截正文。追加不是原子的（崩溃最多在文件末尾留半截会话段，
读取时会跳过并告警）——这是刻意的取舍，为追加每次重写 2MB 不划算。

**备份**：这个目录就是全部状态。停服后整目录复制即可；**不要在运行中只复制一半**。
恢复就是把目录放回去重启，没有任何额外步骤。

## 4. 监控与告警阈值

永久保留 + 不自动过期 ⇒ **磁盘是单调增长的**，所以「增长率」是唯一能提前发现异常的指标，
总量阈值只是兜底。

### 4.1 算法依据（实测标定）

以下数字来自一次真实问答落盘后的测量，不是估算：

| 项 | 实测 |
|---|---|
| 正文：段头 | 49 字节（含 36 字符的会话 id、时间、条数） |
| 正文：一条用户消息 | 48 字节 ≈ `user: ` + 14 个中文字（中文按 UTF-8 3 字节/字） |
| 正文：一条助手消息 | 474 字节（该次回复约 154 字，偏长） |
| 索引：一行 | 113 字节 |
| 审计：一条删除 | 62 字节 |

按「一问一答约 0.4KB、一个会话约 10 条消息」推算：

- 一个会话 ≈ **4KB** 正文 + **0.1KB** 索引 ≈ 4.1KB
- 每用户每天 2 个会话 → **约 8KB/天/用户**
- 100 个活跃用户、每年 250 个工作日 → **约 200MB/年**

当前种子数据只有个位数用户，真实年增长在**十几 MB** 量级。所以下面的阈值给的都是宽裕余量，
目的是抓「增长形态突变」，不是卡容量。

### 4.2 三条阈值

| 指标 | 阈值 | 依据 |
|---|---|---|
| 根目录总量 | **1GB** | 约为「100 用户连续 5 年」的估算用量。到这条线说明规模远超预期，或者有东西在异常增长 |
| 近 24 小时增量 | **20MB/天** | 约为「100 用户」估算值（0.8MB/天）的 **25 倍**，只会被异常触发（例如脚本疯狂建会话） |
| 单用户单日分片数 | **≥ 2** | 出现 `memory-YYYY-MM-DD-2.md` 意味着该用户当天写满 2MB ≈ **500 个会话**，值得看一眼 |

### 4.3 怎么监控

`drone-agent` **没有内建指标端点**（项目没有引入 actuator），所以监控走外部脚本读磁盘。
这样也不需要为监控加依赖：

```sh
#!/bin/sh
# 建议每 10 分钟跑一次（cron: */10 * * * *）
# 需要 GNU find / du（Linux 常见）；macOS 的 BSD find 不支持下面这两个用法
ROOT="${AGENT_MEMORY_ROOT:-./data/agent-memory}"
TOTAL_LIMIT_MB=1024      # 总量阈值 1GB
DAILY_LIMIT_MB=20        # 近 24 小时增量阈值

[ -d "$ROOT" ] || { echo "记忆根目录不存在：$ROOT"; exit 1; }

TOTAL_MB=$(du -sm "$ROOT" | cut -f1)
if [ "$TOTAL_MB" -gt "$TOTAL_LIMIT_MB" ]; then
  echo "记忆目录已达 ${TOTAL_MB}MB，超过阈值 ${TOTAL_LIMIT_MB}MB"
fi

DAILY_MB=$(find "$ROOT" -type f -mtime -1 -exec du -cm {} + 2>/dev/null | tail -1 | cut -f1)
if [ -n "$DAILY_MB" ] && [ "$DAILY_MB" -gt "$DAILY_LIMIT_MB" ]; then
  echo "记忆目录近 24 小时新增 ${DAILY_MB}MB，超过阈值 ${DAILY_LIMIT_MB}MB"
fi

# 单用户单日出现第 2 个分片：该用户当天量异常
find "$ROOT" -type f -name 'memory-*-*-*-2.md' -mtime -1 -print
```

**上线一两周后请回来用真实数据替换 4.1 的估算**：`du -sm "$ROOT"` 看总量、
`find "$ROOT" -type f -mtime -7 -exec du -cm {} + | tail -1` 看周增量，
据此把阈值调到「正常值的 10~25 倍」。**不调也行，但要知道那两个数是怎么来的。**

> 三个阈值中的「近 24 小时增量」在补齐前是空缺的（ADR-0003 把它列为遗留）。
> 本文补齐的只是**阈值与算法**；真正接上告警通道（企业微信 / 邮件 / 值班系统）仍需运维侧配置。

## 5. 工具调用（`agent.tool.*`）

`REQ-AGENT-0004` 给助手加了**工具调用**：问到飞行相关天气时，助手会先**查实时天气**再作答。
配置在 `application.yml` 的 `agent.tool.*`：

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `agent.tool.enabled` | `true` | 总开关。置 `false` 即回到「只会聊天」的纯对话，行为与本需求之前一致 |
| `agent.tool.max-rounds` | `3` | 一次对话最多几轮「模型要工具」的循环；超了就不再给工具，逼模型基于已有结果收尾 |
| `agent.tool.request-timeout` | `5s` | 单次天气接口请求超时（同时是连接超时） |
| `agent.tool.parallel-enabled` | `true` | 是否把本轮的多个**只读**工具并发执行；关掉即逐个执行 |
| `agent.tool.concurrency` | `4` | 并发执行时的线程数上限 |
| `agent.tool.invoke-timeout` | `15s` | 单个工具执行超时（编排层兜底，与工具自身超时是两道闸） |
| `agent.tool.catalog` | 见 5.3 | **工具元数据**（名字 / 描述 / 参数 / 能否并行） |
| `agent.tool.optimize-enabled` | `true` | 编排优化（5.5）总开关。置 `false` 回到 `0005` 的行为（预算 / 重试 / 压缩一并失效） |
| `agent.tool.max-result-chars` | `2000` | 单次工具回填的字符上限 |
| `agent.tool.max-total-result-chars` | `6000` | 一次对话里工具结果的字符**总量**上限；超出只留省略标记 |
| `agent.tool.max-retries` | `1` | 工具「失败」后允许的重试次数 |
| `agent.tool.dangerous` | `[]` | **危险工具清单**（`REQ-AGENT-0006`）：命中则**每次执行都要人工确认** |
| `agent.tool.role-tools` | `{}` | 角色 → 允许使用的工具；危险工具**必须**显式授予角色，否则谁都不可用 |

### 5.1 天气数据源在哪、有什么代价

- 默认实现走 **Open-Meteo**（`geocoding-api.open-meteo.com` + `api.open-meteo.com`），
  **官方免费、无需 Key**：先按城市名做**地理编码**拿经纬度，再取**当前天气**
  （气温 / 风速 / 降水 / 天气代码）。
- 代价：**只覆盖天气，不是通用搜索**；且依赖外网可达 —— 出网受限时请求失败，
  被降级成「暂时查不到」（用户只看到助手说查不到，不会看到报错页）。
- **（已下线，2026-10-21）** 旧的 `get_flight_weather`（Open-Meteo，无需 Key）已由
  `REQ-AGENT-0011` 移除；实时天气改由高德 MCP 工具 `amap__maps_weather` 提供，
  配置见 `agent.mcp.*`，需要环境变量 `AMAP_MCP_KEY`。
  接入方式与排障见 [`MCP接入-初级工程师手册.md`](./MCP接入-初级工程师手册.md)。

### 5.2 回滚

把 `agent.tool.enabled` 置 `false`，重启即可回到纯对话；不涉及数据，无需修复。

> **未在部署环境实测**联网可用性（内网 / 出网策略可能挡住）。上线前请确认 `drone-agent`
> 能访问 `geocoding-api.open-meteo.com`、`api.open-meteo.com` 与 `api.deepseek.com`；
> 不能出网时请关掉开关。

### 5.3 工具元数据在配置里（`agent.tool.catalog`）

`REQ-AGENT-0005` 起，工具的**描述、参数 Schema、能否并行**都写在 `catalog` 里；
代码里的工具只提供**行为**（`name()` + `invoke()`）。两者按 `name` 对齐，
**对不上（重名 / 缺一边）服务会启动失败** —— 这是刻意的，别留到运行时才发现。改描述不必改代码，重启即生效。

**新增一个工具的两步**：① 写一个 `Tool` 实现并注册成 Bean；② 在 `catalog` 里加一条同名记录。

```yaml
agent:
  tool:
    catalog:
      - name: get_flight_weather
        description: 查询指定城市的当前天气（气温、风速、降水），用于判断是否适合无人机起飞。
        parallel-safe: true          # 只读工具才允许并发
        parameters:
          type: object
          properties:
            place: { type: string, description: 城市名，如 北京、上海 }
          required: [place]
```

### 5.4 链路追踪与耗时

每次 `/chat` 生成一个 **`traceId`**（8 位十六进制），贯穿「对话 → 编排 → 模型 → 工具」的全部日志；
每次模型调用与每次工具执行都带**耗时（ms）**。排查某一次请求时，直接按 `traceId` 检索即可串起整条链路。

### 5.5 编排优化（`REQ-AGENT-0007`）

- **受控重试**：工具**失败**时不立即收场 —— 把失败信息交回模型再决断；当**失败轮数超过** `max-retries`
  就**收回工具**、逼模型基于已有结果收尾（不会无限重试）。
- **分级压缩**：超长结果先做**结构化裁剪**（去链接 / 并掉连续重复行），仍超长再走**模型摘要**
  （一次额外模型调用，要快、不算深度思考），最后兜底硬截断。
- **显式预算**：单次上限 + 总量上限（见上表）；超总量的结果**不再回填**，只留一句
  「（本轮工具结果过多，已省略）」，避免把 prompt 撑爆。
- **可观测**：`【工具编排】完成` 这一行里有「共 N 步 / 工具失败 M 轮 / 压缩 K 条 / 总耗时」。
- 一键回退：`optimize-enabled: false` 即回到 `0005` 的行为（旧 4000 截断、无重试、无压缩）。

### 5.6 危险工具治理（`REQ-AGENT-0006`）

危险工具（`delete_device` 这类**不可逆**操作）走**三道门**：

1. **授权**：在 `role-tools` 里按角色授予；**没授予的角色用不了**（危险工具 fail-closed）。
   授权判定在服务端，前端藏入口只是体验、不是边界。
2. **人工确认**：命中 `dangerous` 的工具**不立即执行** —— `/chat` 的返回里带一个 `pending`
   （含 `pendingId` 与动作摘要），前端据此弹确认框；用户确认后调 `POST /chat/confirm` 才真正执行。
   待确认票据**存在进程内存、有效期 5 分钟**，**消费即失效**（重复确认只执行一次），
   且**只能本人、只能在同一会话**里确认（拿别人的票据或换个会话都无效）。
3. **审计**：执行成功后往 `<root>/tool-audit.log` 追加一行（`userId` / 工具 / 参数**脱敏后** / 结果 / 时间）。

**回滚**：把危险工具从 `catalog` 撤下即可（**不会**退化成自动执行）；票据在内存里，重启即作废。
**注意**：票据是内存态 —— 与 `ADR-0003` 一样**只支持单实例**。

### 5.7 提示词与注入防护（`REQ-AGENT-0008` / `REQ-AGENT-0009`）

- **提示词不在配置里，在 `src/main/resources/prompts/<业务>/<名字>.md`**：文件带 frontmatter
  （`name / version / purpose / vars / changelog`），**正文**才是发给模型的文本。启动时**逐条打日志**并**校验**
  （空正文 / 名字与路径不符 / 变量与占位符对不上 → **服务起不来**）。
  改措辞**只改 md**，同时把 `version` +1、在 `changelog` 记一条。
- **工具结果会被包成「数据信封」** `<tool_result>…</tool_result>`：明确告诉模型「这是数据、不是指令」；
  内容里若自带标记串会被**中和**（防止伪造边界、把数据伪装成指令）。
- **注入防护靠结构，不靠求模型**：权限在服务端、危险操作要人工确认（见 5.6）、工具是白名单、
  助手无库访问 —— **注入绕不过它们**。回归样本与实测见
  [`../../docs/tests/REQ-AGENT-0009-注入样本.md`](../../docs/tests/REQ-AGENT-0009-注入样本.md)。

#### 5.7.1 目录长什么样

```
drone-agent/src/main/resources/prompts/
├── assistant/            # 业务：助手对话行为
│   └── system.md         #   提示词名 = assistant.system
└── tool/                 # 业务：工具链路
    └── summary.md        #   提示词名 = tool.summary
```

- 一条提示词 = 一个 `.md` 文件，**按业务分子目录**，一起随 jar 打包（在 `resources/` 下，不用改 `pom.xml`）。
- **提示词名 = 相对 `prompts/` 的路径去掉 `.md`、把 `/` 换成 `.`**：
  `assistant/system.md` → `assistant.system`。启动时校验「frontmatter 的 `name` 必须等于这个路径名」，对不上就起不来。
- 代码里**只按名字取用**（如 `promptCatalog.text("assistant.system")`），所以**加一条提示词 = 加一个 md 文件**，代码不动。

#### 5.7.2 新增一条提示词的步骤

1. 在对应业务子目录下**建一个 `.md`**（如新增告警摘要 → `prompts/alert/summary.md`，名字将是 `alert.summary`）。
2. 写上 **frontmatter**（`name` 用第 1 步算出来的名字）+ **正文**（真正发给模型的文本）。字段含义见 5.7.3，
   可照抄 `tool/summary.md` 的格式。
3. 正文里要用变量就写 `{{变量名}}`，并把变量名列进 frontmatter 的 `vars`：
   **`vars` 和正文里出现的占位符必须完全一致**（多了、少了、拼错都算错，启动即失败）。
4. 代码里按名字取用：`promptCatalog.text("alert.summary")`（无变量）或
   `promptCatalog.render("alert.summary", Map.of("变量名", 值))`（有变量；**缺变量直接抛错**，不会静默留 `{{x}}`）。
5. 本地跑一次 `mvn -q compile` 或启动服务：**启动日志会逐条打印** `已加载 路径 → 名字@版本（vars=…）`，
   确认新提示词在里面、版本正确。任何不合格（空正文 / 名字不符 / 变量对不上 / 重名）都会**让服务起不来**，
   错误信息会指明是哪条、缺什么。

> **改措辞**同样走这条路：只改 md 正文，同时把 `version` +1、在 `changelog` 补一行——
> 这样「换了提示词后行为变了」时，启动日志里的 `名字@版本` 能一句话对上用的是哪版。

#### 5.7.3 frontmatter 字段说明

frontmatter 是文件开头两行 `---` 之间的部分（**只认开头这一处**；正文里不要以独行的 `---` 开头，否则会被当成 frontmatter 结束）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 提示词名，**必须等于文件相对路径**（`assistant/system.md` → `assistant.system`），对不上启动失败 |
| `version` | 是 | 正整数版本号；改正文就 +1。会出现在启动日志里（`名字@版本`） |
| `purpose` | 是 | 一句话说明这条提示词的用途（给人看的，不进模型请求） |
| `vars` | 否 | 正文用到的变量名列表，**必须与正文里的 `{{占位符}}` 完全一致**；无变量写 `[]` |
| `changelog` | 否 | 变更记录，一行一条（如 `- v2 2026-10-16 补 …`）；仅供人查，不做自动校验 |

frontmatter 只支持三种写法（手写轻量解析，不引 YAML 库）：`key: 值`、`key:` 后跟若干 `- 列表项`、`key: [a, b]`。

### 5.8 内部资料检索（`REQ-AGENT-0010`）

让助手用**自然语言检索内部资料**（操作手册、保险方案……），再**依据原文**作答并**注明出处**。

#### 5.8.1 要起哪些东西

| 组件 | 说明 |
|---|---|
| **Milvus** | 向量库，Docker 单机。官方 standalone 脚本即可（含内嵌 etcd/minio）：<br/>`curl -sfL https://raw.githubusercontent.com/milvus-io/milvus/master/scripts/standalone_embed.sh -o /tmp/standalone_embed.sh && bash /tmp/standalone_embed.sh start` |
| **嵌入服务** | 算向量用。**走 embedding API**（OpenAI 兼容的 `/embeddings`），三个环境变量必填：`EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY` / `EMBEDDING_MODEL`（**不配就跑不了**：嵌不了资料、也嵌不了问题）<br/>**实测可用的例子（智谱 GLM）**：`EMBEDDING_BASE_URL=https://open.bigmodel.cn/api/paas/v4`、`EMBEDDING_MODEL=embedding-3`、`EMBEDDING_API_KEY=` 你的 `ZHIPU_API_KEY`；它**输出 2048 维**，所以 `agent.kb.embedding.dimension` 要用 **2048**（或用 `EMBEDDING_DIMENSION` 覆盖） |
| **知识库目录** | `agent.kb.directory`（默认 `./data/knowledge`）。把资料丢进去即可；**部署要挂卷** |

> **端口别连错**：实测 Milvus v2.5.8 的 **REST（`/v2/vectordb/**`）与 gRPC 共用 `19530`**；
> `9091` 只是 management/metrics 端口。所以 `agent.kb.milvus.port` 默认就是 **19530**。

#### 5.8.2 相关配置（`agent.kb.*`）

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关。关掉时**一次检索都不发生**（工具会回「未启用」） |
| `scan-on-startup` | `true` | 启动后在后台扫一次资料目录。**测试环境必须关**——`@SpringBootTest` 会执行启动钩子，开着的话单测会真去调嵌入、写向量库（`src/test/resources/application.properties` 已关） |
| `directory` | `./data/knowledge` | 资料根目录 |
| `top-k` | `5` | 检索返回条数上限 |
| `min-score` | `0.5` | 相似度下限，低于它的丢掉。**实测**（GLM embedding-3）：相关 ≈**0.53**、库里根本没有的 ≈**0.46**，故取 0.5 把两者分开。<br/>⚠️ 设成 `0` 会让**「查不到」永远不会发生**（什么都返回 top-k）。样本很小，应按更大的评估集再调 |
| `perm-rules` | `[]` | **可见范围按路径声明**（见 5.8.4） |
| `default-perms` | `[]` | 没命中任何规则时用；**为空 = 那些资料无人可见**（fail-closed） |
| `chunk.max-chars` / `overlap-chars` | `800` / `100` | 切块上限与相邻重叠 |
| `embedding.base-url` / `api-key` / `model` / `dimension` | 空 / 空 / 空 / `2048` | 嵌入服务；**`dimension` 必须与模型一致**，否则写库会被拒（GLM `embedding-3` = 2048） |
| `milvus.host` / `port` / `collection` | `localhost` / `19530` / `drone_knowledge` | 向量库 |

#### 5.8.3 新增一份资料的步骤

1. **把文件放进知识库目录**（当前**只支持 Markdown**，其它格式的解析器接口已留，后续加）。**不用改资料本身**。
2. **在 `agent.kb.perm-rules` 里给它定可见范围**（见 5.8.4）——没配就按 `default-perms`，两者都空则**谁都看不到**。
3. 重启服务（或在有扫描入口时触发一次扫描）。启动后会**在后台异步**扫目录：新文件入库、**内容变了的才重建**、没变的跳过。
4. 验证：问一句该资料里才有答案的问题，答复里应带**出处**（`文件名 › 章节`）。

> **改名/挪位置 = 新文档**：文档标识由**文件路径**推出；同一个文件改了路径，会被当成一份新资料入库，
> 旧那份的块还在。要清理旧块，把旧路径的文件从目录里删掉并重建索引即可。

#### 5.8.4 可见范围怎么声明（**不改原始资料**）

在配置里按**路径规则**授予：**先命中先用**，都没命中走 `default-perms`，都为空则**无人可见**（fail-closed）。
资料格式五花八门，所以**不要求它们带头信息**，靠「文件在哪」来判断：

```yaml
agent:
  kb:
    perm-rules:
      - path: "**/无人机保险方案.md"     # 相对知识库目录的 glob
        perms: [agent:finance]           # 只有带这个权限码的人能检索到
      - path: "**/*.pdf"
        perms: [agent:chat]
    default-perms: [agent:chat]          # 其余资料默认给这个；空 = 无人可见
```

权限码来自 `drone-server` 的 RBAC（与 `role-tools` 同源）。**过滤在检索阶段完成**——
不是「查出来再不让说」；没有权限的内容**在库里就命中不到**。

#### 5.8.5 回滚与排障

- **一键回滚**：`agent.kb.enabled: false` → 回到纯对话（工具会回「未启用」，不再检索）。
- **Milvus 没起 / 连不上**：服务照常启动（向量库 Bean 是**懒加载**的）；检索会**降级为「查不到」**，不会炸对话。
- **换嵌入模型**：改 `embedding.model` 与 `dimension`（**两者必须匹配**），并**重建集合与索引**——维度变了，旧向量不能再用。
- **集合 schema 不符**（例如环境里留着一个旧版本建的 `drone_knowledge`）：程序会**明确报错**并提示先删除该集合，不会静默写坏数据。

# 技术方案 — REQ-AGENT-0010 内部资料检索（RAG）

> 输入是 [`specs/REQ-AGENT-0010-内部资料检索.md`](../specs/REQ-AGENT-0010-内部资料检索.md)。
> 本文件回答**怎么做**，并证明不会破坏既有东西。决策前提见 [`../decisions/ADR-0006-内部资料检索与向量库.md`](../decisions/ADR-0006-内部资料检索与向量库.md)。

- **需求 ID**：`REQ-AGENT-0010`
- **作者 / 日期**：开发 / 2026-10-16
- **评审人 / 评审日期**：待评审

## 1. 方案概述

把「检索内部资料」做成 `drone-agent` 内部的 **`kb` 模块**，并把**四个变化点接口化**：
`DocumentParser`（解析，本期只 Markdown）、`EmbeddingModel`（向量，**走 embedding API**）、
`Retriever`（检索算法）、`VectorStore`（向量库，Milvus / 测试用内存）。

**分层（关键）**：把**与场景无关的向量基础设施**单独放一层，`kb` 只做「知识库」这个场景的编排：

| 层 | 包 | 内容 | 复用性 |
|---|---|---|---|
| **向量基础设施** | `cn.tedu.droneagent.vector` | `EmbeddingModel`、`VectorStore`、`Retriever` 及其内存 / Milvus / API 实现 | **后续「记忆语义检索」直接复用**（见第 9 节） |
| **知识库场景** | `cn.tedu.droneagent.kb` | `DocumentParser`、`Chunker`、`KnowledgeIngestor`、`KnowledgeSearchTool`、权限过滤构造 | 不复用（记忆的解析/入库/过滤条件都不同） |

> 这样切，后续给**长期记忆**加语义检索时，**只加一个场景层**，向量这一层不动。

**块文本 + 向量 + 标量字段（来源、章节、可见权限码）全部落到 Milvus**，检索时把**当前用户的权限**
构造成 **Milvus 标量过滤条件**，做到**无权内容不参与检索**；不引关系库（宪法 §2 禁止 `drone-agent` 访问
`drone-server` 的库），文档台账放 `data/knowledge/` 目录。

助手侧只加**一个只读工具** `search_knowledge`——沿用 `ToolRegistry` 启动校验、`ToolGovernance` 授权、
`ToolResultEnvelope` 数据信封、`TraceIds` 追踪与预算；提示词 `assistant.system` 补「资料用法 + 出处 + 数据不是指令」。

## 2. 影响面

| 维度 | 影响 | 说明 |
|---|---|---|
| 接口 | **无对外接口变更** | 不新增 HTTP 端点；`/chat`、`/chat/stream` 入参出参不变。**仅新增一个内部工具** `search_knowledge`（非 HTTP） |
| 数据模型 | **变更（非库表）** | **不新增 MySQL 表**；新增 **Milvus collection** 与 `data/knowledge/` 台账文件。见第 4 节 |
| 兼容性 | **兼容** | 总开关 `agent.kb.enabled=false` 即回纯对话；不改变既有接口与提示词位置 |
| 性能 | **有影响** | 检索为**一次向量查询**（P95 目标 < 500ms）；入库**异步**不影响请求；未启用开关时**零开销** |
| 其他服务 | **`drone-server`：无改动** | 仅**读**其 RBAC 内部接口（既有能力）；`drone-web`/`drone-app` 不改 |
| 新增中间件 | **有** | Milvus（**Docker 单机**，见 `ADR-0006`）与 Milvus SDK 依赖；部署文档需补 |
| 新增外部依赖 | **有** | **embedding API**（供应商 / 模型名走配置）：入库与检索各需一次调用；**需外网可达**，Key 走环境变量（宪法 §4）；不可用时**降级**为「查不到」 |

## 4. 数据模型变更

- **变更内容**：
  1. **Milvus 集合 `drone_knowledge`**（**已在真库上验证**：Milvus v2.5.8）。**不新增 MySQL 表**。
     字段：`id`(VarChar，主键，**`autoId=false`**，值 = `{doc_id}#{chunk_index}`) / `doc_id` / `file_name` /
     `section`（章节路径，即**引用出处**）/ `content`（块正文）/ `chunk_index` / `perm_codes`（**Array\<VarChar\>**，可见权限码）/
     `embedding`（FloatVector，**COSINE** 索引）。
     **主键由我们给**，所以「重灌 = 覆盖」，**幂等重建**成立。
  2. **`data/knowledge/`**：原始资料文件 + `manifest.json` 台账（`doc_id / path / content_hash / updated_at / status`）。
     `content_hash` 用于**增量重建**与幂等。
- 【已改·2026-10-16】相对原草案的两处改动（**都经真库验证**）：
  - 集合名与字段名**沿用环境里已有的 `drone_knowledge`**（`id/doc_id/file_name/section/content/chunk_index/embedding`），
    并**补 `perm_codes`、去掉 `autoId`**——原草案的 `kb_chunks / text / section_path / doc_title` 弃用。
    （原集合是旧 schema，**需 drop 后由程序重建**；`MilvusVectorStore` 会在 schema 不符时**明确报错**提示。）
  - **不引 Milvus SDK**：实测 REST 的 `/v2/vectordb/**` 与 gRPC **共用 19530**（9091 只是 management/metrics），
    适配器用 JDK `HttpClient` 直连即可，`pom.xml` 不变。
- **迁移脚本**：**无**（不涉及 MySQL；宪法 §6 的迁移脚本要求不适用）。
- **回滚方案**：关闭开关回纯对话；删除 Milvus collection 与 `data/knowledge/` 即彻底回退，无业务数据需修复。
- **是否需要停机 / 执行窗口**：入库异步，**不需要停机**；首次建索引在一个后台任务里完成。

## 5. 关键设计决策

| 决策点 | 备选方案 | 结论 | 理由 |
|---|---|---|---|
| 能力放哪 | ①**内聚 drone-agent** ②单列服务 | **①** | 复用工具框架/提示词/追踪/线程池；代价是 drone-agent 变重（见 `ADR-0006`） |
| 元数据存哪 | ①MySQL ②**Milvus 标量字段 + 文件台账** ③另起库 | **②** | 宪法 §2 禁访问 drone-server 库；③增中间件。Milvus 标量过滤正好承载权限 |
| 向量库 | ①ES ②pgvector ③**Milvus** | **③（Docker 单机）** | 需求方指定；稠密向量 + 标量过滤一体；**集群本期不用** |
| 解析 | ①**Tika（重）** ②**先只 Markdown** | **②（接口留 ①）** | 先不引重型依赖；`DocumentParser` 接口保证可加 |
| 切块 | ①定长 ②**结构感知 + 定长兜底 + 重叠** | **②** | 保留「文档 › 章节」作为引用出处 |
| 嵌入 | ①本地模型 ②**embedding API** | **②** | 需求方定：**走 embedding API**，供应商 / 模型名**配置化**；**本地模型后续再议**（Q-1） |
| 权限粒度 | ①后过滤 ②**前置过滤（下推 Milvus filter）** | **②** | 「先看到再假装没看到」是越权；前置后越权在结构上不成立 |
| 权限来源 | ①自建 ②**复用 drone-server RBAC** | **②（按权限码）** | 宪法 §4：权限在服务端；**资料按「权限码」打标**，避免第二套权限体系（Q-4） |
| 入库执行 | ①请求线程同步 ②**异步 + 幂等（content_hash）** | **②** | 解析/向量化慢且会失败，不能堵请求线程 |
| 开关 | ①无 ②**`agent.kb.enabled`（默认开）** | **②** | 需可回退（宪法要求可回滚） |
| 降级 | ①抛错 ②**Milvus 不可用时返回「查不到」** | **②** | 不因检索挂了炸掉整条对话（沿用工具失败回填的既有约定） |
| 分层 | ①全塞进 `kb` ②**基础设施（`vector`）+ 场景（`kb`）分开** | **②** | 后续「记忆语义检索」要复用向量层，不切对就得推倒重来（见第 9 节） |

## 7. 风险与回滚

| 风险 | 触发条件 | 影响 | 应对 |
|---|---|---|---|
| Milvus 不可用 | 容器未起 / 网络不通 | 检索失败 | 工具**降级**回「查不到」；开关可整体关闭 |
| embedding API 不可用 | 网络不通 / 限流 / Key 失效 | 无法入库与检索 | 检索**降级**为「查不到」；入库失败进重试；Key 走环境变量（宪法 §4） |
| 嵌入成本与延迟 | 入库量大 / 检索频繁 | 费用与响应时间上升 | 批量入库、异步、结果缓存；**P95 目标见 specs** |
| 切块把表格/代码切碎 | 结构不规则 | 引用不准 | 结构感知优先；定长兜底；保留章节路径 |
| 权限标签漏配 | 资料没命中任何 `perm-rules` 且未配 `default-perms` | 越权可见 | **fail-closed**：这类资料权限码为空，**检索阶段就命中不到**（不是靠模型「别说」） |
| 规则写错（glob 打偏） | `perm-rules` 的路径模式写歪 | 该授的没授 / 不该授的授了 | 启动日志与入库日志都会打印「选中了哪条规则 / 落到默认」；**权限码为空时打 WARN** |
| 索引与原文不一致 | 资料更新未重建 | 引用旧内容 | `content_hash` 变更即重建；重建期间旧索引可用 |
| 单实例限制 | 多实例部署 | 向量库可共享但内存态不一致 | 与 `ADR-0003` 同一议题，**本期仍单实例** |

- **上线方式**：**开关**（`agent.kb.enabled`，默认开；上线初期可先关，验证后开）
- **回滚步骤**：关闭开关 → 回纯对话；必要时删 Milvus collection 与 `data/knowledge/`
- **回滚后数据是否需要修复**：**不需要**（检索不产生业务数据）

## 9. 与「记忆语义检索」的复用边界（为后续预留，本期不做）

> **背景**：现在的长期记忆是**文件**（按天分片正文 + 每用户索引）。资料一大，同样需要「相似度检索」。
> **结论**：**向量基础设施可复用；场景层不复用**。所以本方案的**分层必须一开始就切对**（见第 1 节）。

### 9.1 用哪些、改哪些

| 能力 | 能否复用 | 说明 |
|---|---|---|
| `EmbeddingModel` | ✅ | 直接复用 |
| `VectorStore`（upsert/search/delete） | ✅ | 复用；**建议用独立 collection**（见 9.2） |
| `Retriever`（算向量 → 过滤 → top-k） | ✅ | 复用**接口与原语**；**过滤条件不同** |
| 入库管道 `KnowledgeIngestor` | ❌ | 记忆的写入路径是**随对话增量**（走既有 `MemoryArchiver`/`LongTermSessionLoader`），不是批式入库 |
| `DocumentParser` / `Chunker` | ❌ | 记忆不是文档；切块应沿用**会话 / 日期分片**的既有结构 |
| `KnowledgeSearchTool` | ❌ | 记忆是**每轮自动带上下文**，不是让模型决定「要不要查」 |

### 9.2 记忆检索的三条**硬要求**（与知识库**本质不同**）

1. **只能本人**：过滤条件必须是 `user_id = 当前用户`，**不可放宽**。
   **建议用独立 collection 做物理隔离**——比「同一 collection 里靠 `user_id` 过滤」少一个「写错就漏」的机会。
   **越权看到别人的聊天是最严重的事故**，这一条优先级高于一切。
2. **删除要一致**：用户删记忆时**向量必须一起删**；否则「删了还能被检索出来」= **删除权失效**。
3. **原文是唯一事实源**：**文件仍存原文，向量只是索引**（可重建）。索引丢了能重建，**原文丢了就真丢了**——
   与「长期记忆保留原文、不存摘要」的既有立场一致。

### 9.3 其它代价（如实登记）

- **成本与延迟上升**：每轮问答要**写向量**、每次检索要**算查询向量**；需要阈值 / 批量 / 异步策略。
- **持续增长**：需要「何时从文件升级到向量检索」的触发条件（块数 / 规模阈值）。
- **单实例**：与 `ADR-0003` 一致，不因引入向量而改变。

### 9.4 与本期关系

- **本期不做记忆检索**；本方案只保证**基础设施层与场景层切对**，让后续能力**只加场景层、不动向量层**。
- 该能力**尚未立需求**：需要时另立 `REQ`（届时复用 `vector/` 一整套），**不在本需求范围内夹带**。

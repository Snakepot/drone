# 技术方案 — REQ-AGENT-0016 流式输出与思考过程展示

- **需求 ID**：`REQ-AGENT-0016`
- **作者 / 日期**：AI / 2026-10-22
- **评审人 / 评审日期**：需求方 / 2026-10-22（已确认）

## 1. 方案概述

把模型调用改成**流式**（含流式 tool_calls），在 `ChatService` 增加 `streamStep`；
工具循环复用同一套逻辑，只把「调模型」换成流式版本，并把 reasoning/content 增量实时推给 SSE。
前端改用 `chatStream`，按事件渲染思考块（可折叠、带用时）与逐字正文。

## 2. 影响面

| 维度 | 影响 | 说明 |
|---|---|---|
| 接口 | 修改 | `/chat/stream` 的事件改为按 `type` 区分；仅前端面板消费 |
| 数据模型 | 无 | 思考过程不入库 |
| 兼容性 | 兼容 | `/chat`、`/chat/confirm` 不变 |
| 性能 | 首字更快（流式） | 总 token 不变 |
| 其他服务 | 无 | 只涉及 drone-agent 与 drone-web |
| 提示词 | 修改 | `prompts/assistant/system.md` v8：思考过程用中文（增量） |

## 3. 接口清单

`POST /chat/stream`（SSE）：

| 事件 | 负载 |
|---|---|
| reasoning | `{type, delta}` |
| content | `{type, delta}` |
| status | `{type, text}` |
| done | `{type, reply, reasoningMs, pending?, artifacts?}` |
| error | `{type, message}` |

## 4. 数据模型变更

无。

## 5. 关键设计决策

| 决策点 | 备选 | 结论 | 理由 |
|---|---|---|---|
| 工具循环 | 保留非流式 / 改流式 | **改流式** | 用户要求首字快；工具轮次也要有进度反馈 |
| reasoning 去向 | 入库 / 只展示 | **只展示** | 上下文已有 reasoning 回传机制；UI 文本不重复发 |
| 用时口径 | 首 token / 思考结束 | **请求→首个正文增量** | 与用户感知的「想了多久才出字」一致 |
| 事件协议 | 纯 delta / 带 type | **带 type** | 三种增量语义不同，前端要分别渲染 |
| 思考语言 | 提示词约束 / 服务端翻译 | **提示词约束** | 翻译要每条思考再调一次模型，延迟与成本翻倍；实测指令在带工具时仍生效 |

### 思考语言（增量）

- 规则写在 `prompts/assistant/system.md`「# 其他」节（v8），所有路径共用；
- 文案按用户可见语义写「思考过程用中文」，不暴露 `reasoning_content` 字段名；
- 不做服务端或前端翻译：错译风险高于英文原文，且思考块会慢半拍出现。

## 7. 风险与回滚

| 风险 | 触发 | 影响 | 应对 |
|---|---|---|---|
| 流式 tool_calls 格式差异 | 供应商实现不同 | 工具调不到 | 按 index 合并；解析失败降级为无工具 |
| 思考块跳变 | 多轮工具 | 阅读体验差 | 跨轮累积 + status 提示 |
| 事件协议变更 | 旧客户端 | 前端看不懂 | 仅面板消费；保留 `delta` 兼容分支 |

- 回滚：面板切回 `chat()`，`/chat` 未改，功能不受影响。

## 8. 与项目宪法的一致性

- §4 安全：SSE 鉴权与权限不变；思考内容只展示，不入库。
- §5 测试：解析器为纯函数，可离线单测。
- §7 配置：无新增敏感配置。

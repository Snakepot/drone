# 项目宪法 — 无人机管理平台（drone）

> 本文件只放**长期稳定、跨需求生效**的约束，不放功能需求。
> 每条必须**可检查**。禁止出现「尽量」「原则上」「合理」这类无法判定的措辞。
> 本文件由技术负责人维护，**AI 不得修改**。
>
> **回填说明**：本仓库为存量项目，宪法于 2026-10-12 回填。
> 条款按「应有的标准」写，**现状不达标的部分集中列在末尾「当前差距」**，逐条清零。
> 末尾那一节是对 `templates/constitution.md` 章节结构的**刻意增加**（存量回填才需要），
> 新项目不要照抄这一节。

## 1. 技术栈与版本（冻结）

| 项 | 版本 / 选型 |
|---|---|
| JDK | 17 |
| 框架 | Spring Boot 3.3.3（`drone-server` 与 `drone-agent` **同版本**） |
| 构建 | Maven（**无 wrapper**，用系统 `mvn`） |
| 持久层 | MyBatis 3.0.4（mapper XML 置于 `resources/mapper/`，开启 `map-underscore-to-camel-case`） |
| 数据库 | MySQL 8，库名 `drone`，驱动 `mysql-connector-j` 8.3.0 |
| 鉴权 | jjwt 0.12.6，HS256 |
| Excel | easyexcel 3.3.4 |
| 设备接入 | paho `mqttv3` 1.2.5 |
| 本地缓存 | Caffeine 3.1.8（仅 `drone-agent` 的会话短期记忆用；版本由 Spring Boot BOM 托管，**不手写版本号**） |
| 接口文档 | knife4j 4.5.0（仅 `drone-server`） |
| 管理端 | Node `^22.18 \|\| >=24.12`、Vue 3.5、Vite 8、TypeScript、Element Plus、Pinia、axios |
| 飞手端 | uni-app（Vue 3.4、TypeScript 4.9、Vite 5.2.8） |

- 【强制】上述版本冻结。升级 JDK / Spring Boot / 数据库大版本必须走 `decisions/` 里的 ADR。
- 【强制】不引入 Redis；不引入 Flyway / Liquibase（迁移脚本手工执行，见第 6 节）。
- 【强制】不得引入与上表同类的第二套库（第二个 ORM、第二个 JSON 库、第二个 MQTT 客户端）。
- 【强制】依赖版本在 `pom.xml` 的 `<properties>` 中集中声明，禁止散落。

## 2. 工程结构与依赖方向

- 【强制】四个工程（`drone-server`、`drone-agent`、`drone-web`、`drone-app`）各自独立构建，
  根目录**不设**聚合 pom / workspace。
- 【强制】`drone-server` 按**业务模块**分包（`analytics`/`dashboard`/`device`/`route`/`task`/`user`/`zone`），
  模块内部再分层；**禁止**在顶层 `controller/`、`service/`、`dao/` 下堆积所有模块的类。
- 【强制】依赖方向单向：`web → service → dao`。反向依赖一律禁止
  （`dao` 不得引用 `service`，`service` 不得引用 `controller` 的类）。
- 【强制】`drone-agent` **不得访问 `drone-server` 的数据库**；两服务之间的数据交互
  只走 HTTP 内部接口（`/internal/**`）。
- 【强制】`drone-agent` 不得实现自己的登录；用户身份一律来自 `drone-server` 签发的 Token。
- 【强制】跨服务契约以需求 ID 归档在 `docs/sdd/plans/` 中，改契约必须同步更新该文件。

## 3. 接口契约

- 【强制】统一响应体 `JsonResult`：`{state, message, data}`。`state=200` 表示成功
  （前端同时接受历史值 `0`），`state=500` 表示业务失败。
- 【强制】**业务失败返回 HTTP 200 + `state≠200`**；只有鉴权失败使用 HTTP 状态码
  （`401` 未认证 / `403` 未授权 / `503` 鉴权依赖不可用）。两种风格不得混用。
- 【强制】分页统一用 `PageResult`：`{list, total, page, pageSize}`。
- 【强制】接口文档随代码走：`drone-server` 用 knife4j；新增/修改接口必须能被文档正确反映。
- 【强制】接口变更必须同步更新对应 `docs/sdd/plans/` 的「接口清单」，并给出兼容性结论。
- 【强制】错误码一旦发布，**含义不得改变**，只能新增。（当前只有 `SUCCESS`/`FAIL` 两个，
  逐项错误码表见「当前差距」。）

## 4. 安全红线

- 【强制】所有非公开接口在**统一入口**（`AuthInterceptor`）鉴权；禁止逐接口各写一套。
- 【强制】Token 只承载身份（`sub` 用户 ID、`username`），**不承载角色与权限**；
  权限每次查库补全，以保证「改权限下次请求立即生效」。不得改为把权限塞进 Token。
- 【强制】权限判定在服务端；前端隐藏入口只是体验，不构成安全边界。
- 【强制】凡按 ID 操作资源的接口，**必须校验该资源归属当前用户/租户**，不得只依赖前端不传。
- 【强制】`/internal/**` 只走共享密钥（请求头 `X-Internal-Token`），
  **不得暴露到网关之外**，且不得与用户接口共用同一套凭据。
- 【强制】密钥只走环境变量，配置文件仅留占位（`${VAR:}`）；**真实值不得进仓库**。
- 【强制】后端**不配 CORS**；管理端与飞手端 H5 通过 devServer 代理或网关同源访问。
- 【强制】文件上传限制类型白名单与大小：multipart 全局上限 500MB / 520MB，
  按类型（照片 / 视频 / 日志）的细分上限在业务层判定。
- 【强制】日志不得出现密钥、Token、密码、完整手机号（需脱敏）；
  `Authorization` 请求头属禁止打印之列。
- 【强制】输入一律视为不可信：外部接口必须做服务端参数校验，不得依赖前端校验。

## 5. 测试门槛

- 【强制】单元测试遵循 AIR：自动运行、互不依赖、可重复；**不得依赖真实外部环境**
  （真数据库、真 MQ、真第三方），确需真实依赖的归入集成测试并单独标记。
- 【强制】**每条验收条件必须有对应用例**；做不到的必须在 `plans/` 里写明原因。
- 【强制】覆盖率门槛：核心业务模块行覆盖 ≥ 80%，全项目 ≥ 60%；不得靠排除文件达标。
- 【强制】本节对**前后端同时适用**；前端的适用范围见 `frontend-standards.md` 第 10 节。
- 【强制】修缺陷必须先补一个能复现的失败用例，再修。

## 6. 数据与迁移

- 【强制】表结构变更必须**新增**迁移脚本（`drone-server/docs/sql/migration/`），
  **不得修改已执行的历史脚本**。
- 【强制】迁移脚本按顺序执行、可重复执行（幂等），文件头部写明前提与执行顺序。
- 【强制】表必备三字段：`id`、`create_time`、`update_time`；
  表名与字段名用 `lower_snake_case`，不得使用数据库保留字。
- 【强制】不使用外键与级联，一致性在应用层保证。
- 【强制】业务数据不做物理删除；不使用存储过程。

## 7. 交付与质量门禁

- 【强制】提交信息必须能追溯到需求 ID（`REQ-<模块>-<四位序号>`）。
- 【强制】提交不得包含 `target/`、`node_modules/`、构建产物、IDE 配置、
  真实密钥、业务数据（`data/` 下的附件）。
- 【强制】主干分支 `main` 受保护，禁止直接推送；合并必须经代码评审。
- 【强制】CI 必须跑：编译、静态检查、单元测试；任一失败即不可合并。
- 【强制】一个提交只做一件事；格式化等无行为改动单独提交，不得混进功能提交。

## 8. 违规处理

- 【强制】任何一条【强制】条款被违反，视为该次交付不合格，不得合并。
- 【强制】确需例外时，必须在 `docs/sdd/decisions/` 记 ADR 说明动机、影响与期限，
  并经技术负责人批准；不得口头豁免。

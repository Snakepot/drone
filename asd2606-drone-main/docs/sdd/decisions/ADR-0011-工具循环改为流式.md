# ADR-0011 工具循环改为流式，思考过程只在前端展示

- **状态**：已接受
- **日期**：2026-10-22
- **决策人**：项目负责人
- **记录人**：AI（按规范登记）
- **关联**：[`specs/REQ-AGENT-0016-流式与思考展示.md`](../specs/REQ-AGENT-0016-流式与思考展示.md)、[ADR-0004](./ADR-0004-工具调用与无Key联网搜索.md)

## 背景

ADR-0004 定的是「工具调用只走非流式」：`chatStep` 固定 `stream=false`，前端面板也用非流式 `/chat`。
副作用是**首字延迟 = 整段生成时间**，且深度思考的 `reasoning_content` 完全不可见。

需求方要求：回复逐字出现；思考过程可见、带用时、可折叠（参考 DeepSeek）。

## 决策

### 1. 工具循环改为流式（取代 ADR-0004 的该条结论）

- 模型请求带 `stream:true` 与 `tools`，按 `delta` 解析三类增量：
  `reasoning_content`、`content`、`tool_calls[index]`（`id/name/arguments` 分片）。
- 编排循环的结构不变（轮次上限、治理、暂停、压缩、产物），只把「调模型」换成流式版本。
- `/chat` 非流式接口保留：确认流程（`/chat/confirm`）与回滚路径仍用它。

### 2. 思考过程只在前端展示，不入库

- `reasoning_content` 仍按既有规则在需要时回传给模型（深度思考 + tool_calls 场景），
  但**不写进会话记忆**、不参与后续轮次的合成。
- 理由：避免上下文重复计费；用户要的是「看得到思考」，不是「记住思考」。

### 3. 用时口径：请求发出 → 首个正文增量

- 与用户感知的「想了多久才开始出字」一致，包含网络与推理等待。
- 多轮工具调用时，展示最后一轮的用时；中间轮次以 `status` 事件告知进度。

### 4. SSE 事件按 `type` 区分

- `reasoning` / `content` / `status` / `done` / `error`。
- 旧版 `{delta,error}` 协议只有面板一个消费者，直接替换；前端保留 `delta` 兼容分支。

## 后果

- 正面：首字明显更快；思考可见；工具轮次有进度反馈。
- 负面：流式 tool_calls 的解析复杂度上升；供应商格式差异需容错（按 index 合并，失败降级）。
- 明确**不选**：思考入库、确认流程流式化、保留两套模型调用实现（会漂移）。

# ADR-0008 新增第五个工程 drone-mcp-server，并以用户身份调用公开业务接口

- **状态**：已接受（负责人 2026-10-21 批准方案）
- **日期**：2026-10-21
- **决策人**：项目负责人
- **记录人**：AI（按规范登记）
- **关联**：[`specs/REQ-AGENT-0012-drone-mcp-server.md`](../specs/REQ-AGENT-0012-drone-mcp-server.md)、[ADR-0007](./ADR-0007-MCP客户端选型与工具适配.md)

## 背景

助手已经能通过 MCP 调高德（REQ-AGENT-0011）。需求方要求再建 `drone-mcp-server`，
把 `drone-server` **现有**业务接口暴露成工具，用自然语言操作平台业务。

这带来两个与宪法 §2 的**字面冲突**：

1. 宪法写的是「**四个**工程」；
2. 宪法写的是「两服务之间的数据交互**只走 HTTP 内部接口（`/internal/**`）**」。

## 决策

### 1. 新增第五个独立工程 `drone-mcp-server`

- 独立构建、独立部署，端口 8082，默认只绑回环。
- 与既有四工程一样：单独 `pom.xml`、`spring-boot-starter-parent` 3.3.3、Java 17，根目录仍不设聚合 pom。
- **代价**：多一个需要部署与监控的进程。

### 2. 服务间调用走「公开业务接口 + 用户 JWT」，不走 `/internal/**`

- 调用链：`drone-agent → drone-mcp-server → drone-server 公开接口`，每调用携带**用户本人**的 JWT。
- **不选「服务账号」**：所有操作会记在一个身份下，任何人拿到助手就等于拿到该账号的权限；
  RBAC 与审计都失真。
- **不新增内部接口**：`/internal/**` 表达的是「服务身份」，无法回答「张三能不能删这条航线」；
  若为其加一个 `X-User-Id` 头，等于造了一个可伪造用户的旁路，风险更高。
- 因此本 ADR 明确：**`drone-mcp-server` 的角色是「用户浏览器之外的另一个客户端」**，
  它在协议层做转换，在权限层**不拥有任何特权**。

### 3. 工具目录来自构建期 OpenAPI 快照，而非启动时联网

- 快照提交在 `drone-mcp-server/src/main/resources/openapi.json`，由脚本从运行中的
  `drone-server` 生成；启动只读 classpath，**零外部依赖**。
- 运行时可选后台刷新（有界重试、失败只 WARN），用于发现接口漂移。
- **不选「启动时拉取」**：会强制 `drone-server` 先启动，形成运维上的顺序依赖。

## 后果

- 正面：权限与审计保持真实；工具集合永远对应真实接口；启动顺序无约束。
- 负面：多一个进程；JWT 会经过一跳本机/内网 HTTP，必须限制网络暴露并优先启用 TLS；
  70 个工具每轮约 15k tokens。
- 已知残留风险：写操作在「上游已执行但响应超时」时，编排层的一次重试可能造成重复执行。
  当前用超时分层（10s < 12s < 15s）压低窗口，并在危险工具上要求人工确认。
- 明确**不选**：服务账号、`/internal/**` 加用户头、启动时拉 OpenAPI、手写 70 份工具 Schema。

# ADR-0002 前端纳入严格执行范围

- **状态**：已接受
- **日期**：2026-10-12
- **决策人**：项目负责人
- **记录人**：AI
- **关联**：[ADR-0001](./ADR-0001-存量回填范围.md)

## 背景

ADR-0001 把严格执行范围定在 `drone-agent` 单个工程。随后发现一个矛盾：

`REQ-AGENT-0002` 尚未关闭的两条验收（`AC-7` 失败占位消息不回传、`AC-8` 系统提示词不可替换）
**都落在前端**；`REQ-AGENT-0001` 的 `AC-4`（入口按权限显隐）、`AC-11`（全屏/窄屏）、
`AC-12`（客户端不能覆盖系统提示词）同样在前端。

也就是说：前端若不纳入范围，这些缺口**永远无法按流程关闭**——
规范里登记着缺口的验收条件，却没有任何一条流程能把它关掉。

## 可选方案

| 方案 | 说明 | 成本 |
|---|---|---|
| A. 只纳入 `drone-web` | 管理端纳入，`drone-app` 保持宽松 | 中 |
| B. 纳入两个前端 | `drone-web` 与 `drone-app` 都纳入 | 中高 |
| C. 维持现状 | 仅 `drone-agent`，前端不纳入 | 低（但缺口无法关闭） |

## 结论

**采纳 B**：`drone-web` 与 `drone-app` 都纳入严格执行范围。

> 关于范围的理解，如实说明：「前端」按字面指本仓库的两个客户端工程，
> 故取 B。`drone-app` 目前没有在途改动，所以**眼下的实际影响主要在 `drone-web`**。
> 若本意仅为 `drone-web`，把本 ADR 标记为「已取代」并另立一条即可，不必改本文件。

## 后果

**正面**

- 助手功能的前端验收（`AC-4` / `AC-7` / `AC-8` / `AC-11` / `AC-12`）终于有流程可依。
- 前端与后端交付标准一致，不会出现「一边严一边松」造成的落差。

**负面 / 必须留意的**

- 两个前端目前**没有任何自动化测试**，`package.json` 里连 `test` 脚本都没有。
  纳入严格范围意味着这笔债必须还，否则宪法第 5 节在前端是空的——
  登记一个永远不执行的条款，比不登记更糟。
- 必须补一份**前端规范**：`java-standards.md` 管不到 TS / Vue。
  已补为 [`../frontend-standards.md`](../frontend-standards.md)。
- 严格范围由 1 个工程扩到 3 个，执行成本上升；`drone-server` 仍不在内。

## 未决事项

- `drone-server` 的**新增改动**是否严格按规范执行，仍未拍板（同 ADR-0001 的未决事项）。

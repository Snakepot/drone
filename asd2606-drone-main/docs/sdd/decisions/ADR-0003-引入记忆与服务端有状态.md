# ADR-0003 引入会话级与长期记忆，服务端转为有状态

- **状态**：已接受
- **日期**：2026-10-12
- **决策人**：项目负责人
- **记录人**：AI（按规范登记）
- **关联**：[ADR-0001](./ADR-0001-存量回填范围.md)、[ADR-0002](./ADR-0002-前端纳入严格范围.md)
- **本决策推翻**：`REQ-AGENT-0002` 中「服务端无状态、历史由客户端持有」的选择

## 背景

`REQ-AGENT-0002` 当初明确选择「服务端无状态、历史由前端持有」，并把这个选择的代价
如实登记为待定项 Q-1：历史由客户端提供 ⇒ **客户端可伪造 `assistant` 轮次**，
现有防线（角色白名单 + 每轮重发系统提示词）只能缓解、不能阻断。

同时该方案的体验缺陷也已显现：刷新页面即失忆、不跨设备、长对话靠客户端反复回传全量历史。

现在要做**会话级短期记忆**（内存）与**长期记忆**（文件），这两件事都要求服务端自己持有状态，
因此必须先推翻上面那条决策，并说清代价。

## 决策

### 1. 服务端转为有状态；暂时不考虑多实例

- 短期记忆放**进程内存**，长期记忆落**本地文件**，两者都无法跨实例共享。
- 因此**显式放弃横向扩展与多实例负载均衡**；本决策期内按单实例部署。
- 重启会丢失内存中的会话；长期记忆在文件里，重启后可按需重新加载恢复。

### 2. 长期记忆存原文，不存摘要

- 决策理由（决策人）：摘要会丢失原始信息，不可接受。
- 已知后果：容量比摘要方案大一到两个数量级，**必须**靠「按用户分目录 + 按日期分文件 +
  索引」把单文件大小封顶，并给出容量增长预期。分片不是优化项，是前提。

### 3. 长期记忆永久保留；提供删除会话能力

- 不设自动过期，不主动删。
- 提供**删除会话**：先做单会话删除，后续可扩展为多选批量删除。
- 因为存的是原文且永久保留，**删除功能不是锦上添花，是必要项**。

### 4. 短期记忆用 Caffeine

- 覆盖此前「不引入缓存库、用 `LinkedHashMap` 自实现 LRU」的建议。
- 收益：拿到成熟的容量上限、过期、LRU 与统计，且不必自己维护 LRU 的并发正确性。
- 这属于宪法第 1 节「新增依赖必须评审」的范畴，本决策即评审结论。

## 后果

**正面**

- 上下文不再依赖客户端提交，**从根上解决** `REQ-AGENT-0002` 的 Q-1 残余风险。
- 刷新页面不再失忆，为跨会话、「上次聊过什么」这类能力打底。
- Caffeine 免去自研 LRU 的并发坑。

**负面 / 必须留意的**

- **横向扩展能力主动放弃**。将来要多实例，必须回头改这条决策。
- 存原文 + 永久保留 ⇒ **磁盘单调增长**。分片、滚动、归档与容量监控必须一起做，
  否则文件会涨到不可维护。
- 单实例 + 本地文件 ⇒ 部署**必须挂卷**，否则容器重建即丢长期记忆。
- **越权风险上升**：记忆按 `userId` 分区，读写都必须严格校验归属
  （宪法第 4 节「按 ID 操作资源必须校验归属」直接适用）。读错分区即是越权。
- **隐私面扩大**：原始对话长期落盘。需要脱敏、访问与删除的审计（见未决）。

## 未决事项

以下尚未拍板，**在 `REQ-AGENT-0003` 的规格定稿（S2）前必须清空**：

1. 会话空闲多久算结束并落盘。
2. 注入模型时记忆的 token / 条数预算。
3. 长期记忆文件的根目录（配置项名与默认值）与单文件滚动阈值。
4. 删除的语义：删内存会话是否**同时**删长期文件？物理删除还是留墓碑？是否留审计。
5. 落盘内容是否需要脱敏。
6. 承诺的容量增长预期（用于运维监控的告警阈值）。

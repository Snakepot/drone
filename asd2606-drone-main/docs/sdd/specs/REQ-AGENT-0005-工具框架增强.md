## 1. 背景与目标

`REQ-AGENT-0004` 只接了**一个**工具（查飞行天气），编排是「同轮内串行执行」。
一旦工具涨到 N 个，三处不足会变成真问题：

1. **注册靠手工且会静默出错**：现在 `ToolConfig` 里一个工具一个 `@Bean`；
   而 `ToolCallingService` 把工具塞进 `Map<name, tool>`，**同名工具会静默覆盖**，错在运行时才暴露。
2. **耗时叠加**：模型一次返回的多个 `tool_calls`（实测出现过一次两个）现在是**逐个串行**执行，
   总耗时 = 工具1 + 工具2 + ……，而这些调用本可并发。
3. **日志能看流程、看不出快慢**：有逐轮叙述，却没有**耗时**，也没有把一次请求的多层日志串起来的
   **相关 id**，做性能分析 / 审计定位要人工拼。

目标：让工具框架在「N 个工具」的规模下**依然好用**——**加工具够简单、注册不会错、多个只读工具能并发、日志能一眼定位到一次请求的完整链路与耗时**。

## 2. 范围

### 做（In Scope）

- **工具元数据外置**：工具的 **name / description / 参数 Schema / 能否并行（有无副作用）**
  由**配置文件**声明；代码里的工具类**只保留行为**（`invoke`），**不再硬编码** description / params
- **`ToolRegistry`（新）**：启动时把「配置文件里的**元数据**」与「代码里的**行为**」按**工具名**合并并校验——
  名字唯一、**元数据与行为一一对应**（有行为没元数据、或有元数据没行为都算错）、参数 Schema 合法；
  **不合格直接启动失败**（fail fast）。编排层只依赖它，不再自己拼 `Map`
- **同轮并行执行**：模型在一轮里返回的多个 `tool_calls`，**在同一轮内并发执行**；
  **回填顺序仍与 `tool_calls` 顺序一致**（`tool` 消息要与 `tool_call_id` 一一对应）
- **单工具超时**：任一工具超时/异常，只影响**它自己**（回填失败结果），不拖垮其他工具与整条对话
- **可配置**：并行开关、并发上限、单工具超时（并入 `agent.tool.*`）
- **链路追踪**：日志补 **耗时**（每次模型调用、每次工具执行、整轮总耗时）与
  **`traceId`**（由 `drone-agent` 生成，贯穿一次 `/chat` 的模型 + 工具 + 数据源所有日志行）

### 不做（Out of Scope）

- **不做跨轮并行**：ReAct 的因果顺序（第 N 轮的结果是第 N+1 轮的输入）不可并行
- **不并行有副作用的工具**：本期只并行**只读**工具；写/危险工具走 `REQ-AGENT-0006`
- **不做「按环境 / 按租户的工具启用白名单」**（Q-5 结论：本期不做）
- **不做工具行为的动态加载**：本期只把**元数据**移到配置文件，**不做到**「配置里加一条就有新工具行为」——
  有行为的工具仍需在代码里实现
- **不引入指标系统**：项目未引入 actuator（宪法第 1 节），本期只靠日志
- 不改 `/chat` 的入参出参与前端行为

## 3. 验收条件

| 编号 | 前置（Given） | 操作（When） | 预期（Then） |
|---|---|---|---|
| AC-1 | 两个工具在**配置里重名**，或**行为与元数据对不上** | 服务启动 | **启动失败**，错误信息指明问题所在（不是运行时才暴露） |
| AC-2 | 模型一轮返回 **2 个只读**工具调用 | 执行该轮 | 两者**并发**执行，整轮耗时 ≈ 较慢那个（**不是两者之和**）；回填顺序与 `tool_calls` 一致 |
| AC-3 | 其中一个工具**超时**或抛异常 | 执行该轮 | 该工具回填**失败结果**；**其他工具照常完成**；整条请求**不返回 500** |
| AC-4 | 一次含工具调用的 `/chat` | 查看日志 | 每次模型调用与每次工具执行都有**耗时**；该次请求的**所有**相关日志带**同一个 `traceId`** |
| AC-5 | 关闭并行（配置） | 一轮含 2 个工具调用 | 行为与**现在完全一致**（串行） |
| AC-6 | 现有 1 个工具 | 新增第 N 个工具 | **加一条配置（元数据）+ 一个行为 Bean** 即可，**不改**编排层代码 |
| AC-7 | 工具的 description 在配置文件里 | 改配置里的 description 并重启 | 新描述**即刻生效**；代码里（如 `WeatherTool`）**没有**硬编码的 description / params |
| AC-8 | 任一工具调用 | 查看日志 | **不含** API Key / `Authorization`（沿用 `REQ-AGENT-0004` 的红线） |

### 非功能要求

- 性能：2 个各 1s 的只读工具，并行后整轮 ≤ **约 1.3s**（串行约 2s）；并发上限默认值见 Q-2
- 容量：本期不做要求
- 安全：日志脱敏红线不变
- 兼容：`/chat` 契约不变；`agent.tool.enabled=false` 仍回到纯对话

## 4. 约束与依赖

- 依赖现有 `Tool` / `ToolDefinition` / `ToolResult` / `ToolCallingService` / `ToolProperties`
- 需为「工具能否安全并行」补一个**声明**（工具自述有无副作用）——见 Q-1
- 与 `REQ-AGENT-0006` 有边界：**是否有副作用**这个声明，正好也是治理的输入；两边要**共用同一份元数据**，
  避免各写一套

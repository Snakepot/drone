## 1. 背景与目标

`REQ-AGENT-0001` 交付后暴露一个问题：连续问「你好」「你好」「我们都聊了什么」，
助手回答「这是我们第一轮对话」——它记不住前面说过的话。

根因：`/chat` 是无状态的，前端只把**当前这一句**发过去，后端组装的请求体里
永远只有「系统提示词 + 用户这一句」，历史从未进入模型的上下文。

目标：让助手在一次对话内**记得住前文**，追问「刚才那个」「我的机型是什么」时能正确作答。

## 2. 范围

### 做（In Scope）

- 对话请求携带完整历史；助手能引用前面几轮的内容
- 历史里的角色只放行 `user` 与 `assistant`
- 历史长度设上界（只保留最近 20 条）
- 入参非法时返回明确的业务错误（`state 400`）而非静默降级
- 前端每次发送整段历史；失败时补的占位提示不回传给模型

### 不做（Out of Scope）

- 不做服务端会话存储（历史仍由前端持有，服务保持无状态）
- 不做多会话管理（不支持「新建对话」「历史会话列表」）
- 不做跨刷新保留（刷新页面即清空；也不落 localStorage）
- 不做历史摘要压缩（只做条数截断）

## 3. 验收条件

| 编号 | 前置（Given） | 操作（When） | 预期（Then） |
|---|---|---|---|
| AC-1 | 已登录且有权限 | 第一轮告知「我负责华东区，机型 M300」，第二轮追问「我的责任区域和机型是什么」 | 回复正确引用「华东区」「M300」 |
| AC-2 | 同上 | 请求的 `messages` 里含 `role: "system"` | 返回 `state 400`，消息说明存在不允许的 role |
| AC-3 | 同上 | `messages` 为空数组 | 返回 `state 400`，消息说明不能为空 |
| AC-4 | 同上 | `messages` 最后一条是 `assistant` | 返回 `state 400`，消息说明最后一条必须是用户提问 |
| AC-5 | 同上 | 传入 30 条历史 | 只取最近 20 条进入模型上下文，请求成功 |
| AC-6 | 同上 | 截断后开头落在 `assistant` 上 | 该孤立回复被去掉，不出现「没头没尾的助手发言」 |
| AC-7 | 上一轮请求失败、界面上有「（请求失败：…）」占位 | 再发一条新提问 | 该占位**不进入**发给模型的历史 |
| AC-8 | 同上 | 任意请求 | 发给模型的 `messages` 第一条始终是服务端配置的系统提示词，客户端无法替换 |

### 非功能要求

- **成本与延迟**：历史条数设上界（20 条），避免聊得越久上下文越长、成本与首字延迟持续上涨。
- **安全**：历史由客户端提供，等于**客户端可控输入**，必须按不可信数据处理（角色白名单）。

## 4. 约束与依赖

- 依赖 `REQ-AGENT-0001` 的鉴权链路（`agent:chat`）与前端面板。
- 契约变更：`POST /chat`、`POST /chat/stream` 的入参由 `{message}` 改为
  `{messages:[{role,content}]}`。**这是破坏性变更**；当时唯一调用方是同仓库前端，
  已同步修改，无外部调用方受影响。
- 依赖 `GlobalExceptionHandler` 将 `IllegalArgumentException` 映射为 `state 400`。

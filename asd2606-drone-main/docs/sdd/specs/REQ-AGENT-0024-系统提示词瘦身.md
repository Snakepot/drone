# 规格 — REQ-AGENT-0024 系统提示词瘦身

- **需求 ID**：`REQ-AGENT-0024`
- **提出人 / 日期**：需求方 / 2026-10-23
- **负责人**：AI（按 SDD 执行）
- **前置**：`REQ-AGENT-0008`（提示词工程化）、`REQ-AGENT-0023`（评估集）

## 1. 背景与目标

系统提示词每轮都发，是最稳定的固定成本之一。v9 渲染后约 **1,844 token**（估算口径），
其中有不少重复与冗长内容：

- 工具名清单（高德 7 个、业务工具 3 个）在工具定义里已有；
- 「先查后写 / 写前复述 / 权限不足 / 分页」在多个小节重复；
- 拒答一节带大段反例，占用篇幅；
- 业务范围用 10 条列表，示例过多。

目标：**在不改变行为的前提下，把提示词压到约一半**，并用评估集证明没有回归。

## 2. 范围

### 做（In Scope）

- 合并重复规则（工具总则、地图、业务工具、Skill、记忆、知识各节只保留独有约束）；
- 移除工具名清单（工具定义里已有名称与描述）；
- 压缩业务范围与拒答话术，保留判断标准与示例语气；
- 版本升到 v10，changelog 记录；
- 用 `REQ-AGENT-0023` 评估集对比前后：通过率、上下文 token、延迟。

### 不做（Out of Scope）

- 不改变任何业务规则（权限、确认、出处格式、记忆触发、Skill 顺序）；
- 不拆分多份提示词或动态拼装；
- 不改工具描述与 Skill 正文。

## 3. 验收条件

| 编号 | 前置 | 操作 | 预期 |
|---|---|---|---|
| AC-1 | v10 提示词 | 看账单 | 系统提示词 token 从 ~2,002 降到 ≤1,200（**降幅 ≥40%**） |
| AC-2 | 评估集（9 条） | 运行 | 通过率仍为 **9/9** |
| AC-3 | 评估集 | 对比 | 平均上下文 token 下降；缓存命中率在预热后仍 ≥95% |
| AC-4 | 拒答用例 | 问「写一首诗」 | 仍拒绝，回复含「抱歉」，不调用工具 |
| AC-5 | 知识 / 记忆 / Skill 用例 | 运行 | 仍触发对应工具，出处格式与触发规则不变 |
| AC-6 | 提示词加载 | 启动 | `PromptCatalog` 校验通过（变量、frontmatter 合法） |

### 非功能要求

- 只改 `prompts/assistant/system.md`，不改 Java；
- 回滚只需把提示词版本切回 v9（文件历史）。

## 4. 约束与依赖

- 行为验证依赖评估集与真实模型；单测只能证明加载与占位符正确；
- 提示词压缩会改变前缀指纹，缓存需要重新预热（预期）。

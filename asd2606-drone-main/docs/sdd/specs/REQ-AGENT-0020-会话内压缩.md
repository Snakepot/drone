# 规格 — REQ-AGENT-0020 会话内压缩（Compaction）

- **需求 ID**：`REQ-AGENT-0020`
- **提出人 / 日期**：需求方 / 2026-10-23
- **负责人**：AI（按 SDD 执行）
- **前置**：`REQ-AGENT-0003`（会话与长期记忆）、`REQ-AGENT-0017`（上下文账单）

## 1. 背景与目标

当前会话内上下文**只取最近 20 条**（`ContextAssembler.SESSION_MESSAGE_LIMIT`），
更早的消息被**静默丢弃**：

- 模型不知道「前面还有内容」，长对话会突然断片、重复提问、前后结论矛盾；
- 会话本身还保留着这些消息（上限 200 条），只是模型看不到。

目标：把超出的早期消息**压缩成一段背景摘要**，与最近若干条一起注入，让长对话不断片。

## 2. 范围

### 做（In Scope）

- 会话内未摘要的消息超过阈值（默认 30 条）时，把「除最近 10 条以外」的部分
  交给模型压成一段中文摘要（≤1,500 字）；
- 摘要作为一条 `system` 消息（类别 `历史摘要`）注入在最近消息之前；
- 摘要缓存在内存中的 `Session` 上，**后续轮次不重复摘要**，直到又攒够一个阈值；
- 摘要失败（模型不可用/超时/空结果）时**回退到现有行为**（只取最近 20 条），请求不失败；
- 摘要输入有上限（默认 12,000 字符），超出时保留更接近当前时间的部分；
- 账单新增 `历史摘要` 分类；日志打印压缩条数、摘要字数。

### 不做（Out of Scope）

- **摘要不落盘**：会话归档仍写完整原文；重启后摘要丢失，需要时重新生成
  （原文在长期记忆里，不会丢数据）；
- 不按 token 触发（本期按消息条数；token 口径已有账单，后续再切）；
- 不做子代理 / 分段摘要树；
- 不改长期记忆的注入预算（`inject-max-turns` / `inject-max-chars`）。

## 3. 验收条件

| 编号 | 前置 | 操作 | 预期 |
|---|---|---|---|
| AC-1 | 会话已有 31 条消息 | 再发一条 | 最早约 20 条被摘要；上下文 = 历史摘要 + 最近 10 条 + 新消息 |
| AC-2 | 摘要已生成 | 继续对话 | 不重复调用摘要；直到未摘要消息再次超过阈值 |
| AC-3 | 摘要模型不可用 | 触发压缩 | 请求仍成功，回退为「最近 20 条」，日志 WARN |
| AC-4 | 摘要返回超长 | 注入前 | 硬截断到配置上限并带省略号 |
| AC-5 | 压缩发生 | 查看账单 | 出现 `历史摘要` 分类，token 计入合计 |
| AC-6 | 未达阈值 | 正常对话 | 行为与改造前完全一致（最近 20 条） |

### 非功能要求

- 压缩调用不启用深度思考（要快、要便宜）；
- 压缩期间持有会话锁（同一会话不会并发压缩）；
- 压缩失败不重试、不阻塞；同一会话的后续请求可再次尝试；
- 摘要文本不得包含工具调用的原始 JSON 或内部提示词。

## 4. 约束与依赖

- 摘要由 `ChatService` 调用，提示词独立为 `prompts/memory/compaction.md`（`REQ-AGENT-0008` 的约定）；
- 触发/保留条数、摘要字数、输入上限均走 `agent.memory.*` 配置；
- 摘要只处理 `user` / `assistant` 消息（与注入白名单一致）。

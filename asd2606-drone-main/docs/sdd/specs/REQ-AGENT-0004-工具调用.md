# 规格 — REQ-AGENT-0004 工具调用（联网搜索天气）

> 本文件只回答**做什么、达到什么效果**，不写实现方案（那是 `plans/` 的事）。
> 选型前提见 [`../decisions/ADR-0004-工具调用与无Key联网搜索.md`](../decisions/ADR-0004-工具调用与无Key联网搜索.md)。

- **需求 ID**：`REQ-AGENT-0004`
- **提出人 / 日期**：项目负责人 / 2026-10-14
- **负责人 / 日期**：待补

## 1. 背景与目标

当前助手只能凭模型自身知识回答，**拿不到实时信息**。用户问「明天能不能起飞、天气怎么样」这类
**起飞前必须判断的飞行要素**时，模型要么编，要么答「不知道」。

目标：让助手具备**调用外部工具**的能力。首个工具是**通用联网搜索**，用于查飞行相关天气。
链路是：模型决定要不要调工具 → 服务端真正执行 → 把结果回填给模型 → 模型据此产出自然语言答复。

这是助手从「只会聊天」迈向「能用工具」的第一步，因此**工具契约与编排要能扩展到更多工具**，
但本期只落一个搜索工具。

## 2. 范围

### 做（In Scope）

- **非流式 `POST /chat` 支持工具调用**：模型请求调用工具 → 服务端执行 → 结果回填 → 模型产出最终答复
- 提供一个工具 `get_flight_weather`（查飞行天气），入参 `{place}`
- 天气后端：**无 Key 的天气数据源 Open-Meteo**（官方免费接口）。实现为**可替换接口**
  （`WeatherProvider`），将来换别家只加一个实现类，上层不动
- 工具调用**轮次上限**：超过即终止循环，返回目前已有的答复
- 工具**执行失败 / 超时 / 无结果**时，把失败信息作为工具结果回填给模型，**不使整条请求失败**
- **system prompt 增补**：放行「飞行相关天气」；其余非业务问题仍按现状委婉拒绝
- 工具调用全过程**日志**：一进一出、入参出参**脱敏**

### 不做（Out of Scope）

- **流式 `POST /chat/stream` 不支持工具调用**（本期明确不做，保持现状）
- 不接入需 Key 的搜索提供商（只留接口，不配置真实 Key）
- 不做天气以外的工具；不做多工具并存
- 不做**工具结果的独立持久化 / 缓存**
- **不把工具调用的中间消息写入会话记忆**——会话只新增「用户消息 + 最终助手答复」两条
- 不改 `/chat`、`/chat/stream` 的**响应契约**，不新增接口

## 3. 验收条件

| 编号 | 前置（Given） | 操作（When） | 预期（Then） |
|---|---|---|---|
| AC-1 | 已登录且有 `agent:chat` 权限 | 问飞行相关天气（如「明天北京适合起飞吗，天气怎么样」） | 模型发起 `get_flight_weather`；服务端执行并把结果回填；最终返回**自然语言**答复，答复中**不含**原始 JSON 或工具调用结构 |
| AC-2 | 同上 | 问**纯生活**天气（如「明天要带伞吗」） | **不调用工具**，按现有规则**委婉拒绝** |
| AC-3 | 同上 | 问与天气无关的业务问题（如「M300 保养周期」） | **不调用工具**，正常回答 |
| AC-4 | 搜索后端超时或返回错误 | 问飞行天气 | 请求**不返回 500**；模型**如实告知**暂时查不到，不编造数据 |
| AC-5 | 模型连续请求工具 | 反复调用超过轮次上限 | 循环终止并返回已有内容；**不会无限调用** |
| AC-6 | 任一工具调用 | 查看服务端日志 | 日志含**工具名 / query / 结果条数或摘要**，且**已脱敏**；**不含** API Key、`Authorization` |
| AC-7 | 未配置 `DEEPSEEK_API_KEY` | 任一次对话 | 行为与现状一致（返回「未配置」提示），**不因新增工具而改变** |
| AC-8 | 一次发生了工具调用的对话 | 查看该会话的历史 | 会话中**只新增两条**：用户消息 + 最终助手答复；**无**工具中间消息 |

### 非功能要求

- 性能：单次工具调用超时上限 **5s**（可配）；`/chat` 整体超时相应放宽到覆盖**一次**工具往返
- 容量：本期不做要求（工具结果不落盘）
- 安全：搜索**无 Key**；工具入参与结果**入日志前脱敏**；不得外泄 `Authorization`
- 兼容：`/chat` 出参与现有 `{state, message, data:{reply}}` 一致；流式路径**不受影响**

## 4. 约束与依赖

- 依赖 DeepSeek 的 **Tool Calls**（OpenAI 兼容格式）
- **复用当前模型配置**（`deepseek-flash`）——T-8 已实测其**支持** function calling
- 依赖 **Open-Meteo**（无 Key 的官方免费接口）取实时天气；运行环境需**外网可达**

> **补记（2026-10-14，T-8 验证后，已定稿）**：Q-1 最初定的「无 Key 的通用搜索（DuckDuckGo）」
> **被实测推翻** —— DuckDuckGo 对自动访问返回 HTTP 202 首页（反爬），拿不到任何结果。
> 经决策人复议，**改定 Open-Meteo**（无 Key、天气专用、实测可用）。
> 由此工具的语义从「通用搜索」收窄为「查飞行天气」，工具名相应改为 `get_flight_weather`。

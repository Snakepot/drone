# 规格 — REQ-AGENT-0025 上下文账单可视化

- **需求 ID**：`REQ-AGENT-0025`
- **提出人 / 日期**：需求方 / 2026-10-23
- **负责人**：AI（按 SDD 执行）
- **前置**：`REQ-AGENT-0017`（账单）、`REQ-AGENT-0022`（指纹）

## 1. 背景与目标

账单目前只在 **agent 日志**里，用户与管理员都看不到：

- 用户不知道「这一问花了多少上下文、缓存命中多少」；
- 管理员无法按天/按类别分析「钱花在哪」，也无法发现某个角色/流程异常昂贵；
- 排查「为什么变贵了」只能翻日志文件。

目标：

1. **让每次回答都能看到本次消耗**（聊天面板内，随回复展示）；
2. **让管理员有一个账单页面**：按天、按类别、按工具汇总，支持筛选；
3. 只存**元数据**（token、工具名、时间），不存任何对话正文。

## 2. 范围

### 做（In Scope）

- 新增 `BillRecord` 与 `BillStore`：每次模型调用落一条 JSONL（按天分文件）；
- SSE `done` 事件携带本次请求的账单摘要；
- 聊天面板在助手消息下展示「本次消耗 X token · 缓存 Y%」，可展开分类明细；
- 新增账单查询接口（自己的账单）与汇总接口（管理员）；
- 管理端新增「助手账单」页面：KPI 卡片、按类别堆叠图、工具归因、最近请求表；
- 保留 30 天，启动/每日清理过期文件。

### 不做（Out of Scope）

- 不做人民币计费（单价随供应商调整，单独配置再说）；
- 不做配额/告警（下一阶段）；
- 不存对话内容、不存工具参数与结果；
- 不做多实例共享（JSONL 是单实例文件；需要时再迁 DB）。

## 3. 验收条件

| 编号 | 前置 | 操作 | 预期 |
|---|---|---|---|
| AC-1 | 一次普通对话 | 看助手消息下方 | 显示本次 token 与缓存命中率，数值与日志一致 |
| AC-2 | 同上 | 展开明细 | 显示系统/会话/工具定义/工具结果/摘要的分类 token |
| AC-3 | admin 打开账单页 | 选择「今天」 | 看到请求数、总 prompt、平均上下文、命中率、指纹数 |
| AC-4 | 同上 | 看图表 | 按天趋势、分类构成、工具调用 Top N 三张图 |
| AC-5 | pilot 登录 | 调账单接口 | 只能看到自己的记录；`scope=all` 返回 403 |
| AC-6 | 重启服务 | 打开账单页 | 历史仍在（JSONL 落盘） |
| AC-7 | 任意账单 | 检查文件/接口 | 不含对话正文、工具参数、Token |

### 非功能要求

- 落盘为**追加写**，单条 < 2KB，失败只记 WARN，不影响对话；
- 查询接口支持 limit，默认最近 50 条；
- 前端图表使用已有 `echarts`，不新增依赖；
- 30 天保留，单文件按天滚动。

## 4. 约束与依赖

- `drone-agent` 没有数据库，沿用文件存储（与记忆子系统一致）；
- 账单数据来自 `ContextBill` 与 `TokenUsage`，不重新计算；
- 管理端与助手共用同一套登录与权限（`agent:chat`），跨用户查询需 admin 角色。

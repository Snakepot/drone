# 规格 — REQ-AGENT-0018 工具按角色与权限裁剪

- **需求 ID**：`REQ-AGENT-0018`
- **提出人 / 日期**：需求方 / 2026-10-23
- **负责人**：AI（按 SDD 执行）
- **前置**：`REQ-AGENT-0017`（上下文账单）

## 1. 背景与目标

一次请求的上下文里，**工具定义占 83%**（REQ-AGENT-0017 实测：10,362 / 12,463 token）。
但当前 73 个工具**对所有角色全量下发**：

- 飞手能看到「删除设备」「角色授权」等工具（执行时会被拦，但模型仍会尝试）；
- 大屏只读角色能看到全部写操作工具；
- 工具越多，模型选错工具的概率越高。

目标：**只把当前用户「看得见也用得上」的工具下发给模型**，同时保持执行侧授权不变。

## 2. 范围

### 做（In Scope）

- 新增**可见性规则**（配置化）：工具名模式 → 需要的权限码，任一满足即可见；
- 角色维度复用现有 `role-tools`：被它限制的工具，只有名单内的角色可见；
- 两个维度是 **AND**：角色与权限都通过才下发；
- 未匹配任何规则的工具**默认可见**（地图、知识检索、Skill 等元工具）；
- 每轮请求只计算一次可见工具列表；日志打印可见数 / 总数与拦截原因；
- 上下文账单里的「工具定义」行自动反映裁剪后的数量与 token。

### 不做（Out of Scope）

- **不改执行侧授权**：`ToolGovernance.allows` 仍在每次执行前再判一次（纵深防御）；
- 不做「按对话意图动态加载工具组」（如日报只给分析工具），后续需求；
- 不改 `drone-mcp-server` 的工具元数据（不引入权限字段）；
- 不改前端。

## 3. 验收条件

| 编号 | 前置 | 操作 | 预期 |
|---|---|---|---|
| AC-1 | admin 账号 | 发起对话 | 可见工具 = 全部可执行工具（73 个减去被 MCP 排除的），账单工具 token 与改造前一致 |
| AC-2 | pilot 账号 | 同上 | **看不到** `drone__user_*`、`drone__system_*`、`drone__alert_*`；能看到设备与任务执行类工具 |
| AC-3 | screen 账号 | 同上 | 只看到读类工具；**看不到** `task_create` / `task_dispatch` / `device_add` / `zone_delete` 等写工具 |
| AC-4 | 任意账号 | 同上 | `search_knowledge` / `use_skill` / `read_skill_resource` 与未配置规则的 MCP 工具（地图）仍可见 |
| AC-5 | 任意账号 | 查看日志 | 有且仅有一条 `【工具裁剪】`，含可见/总数、角色拦下数、权限拦下数、被隐藏的工具名（截断） |
| AC-6 | pilot 强行触发隐藏工具（如显式要求删设备） | 观察回复 | 模型侧没有该工具可调；即使构造调用，执行侧仍按原规则拒绝 |

### 非功能要求

- 裁剪是纯内存匹配，73 个工具 < 1ms；
- 规则**先匹配先用**，顺序在配置文件里显式可读；
- 规则写错（未知权限码）不影响启动——权限码由 `drone-server` 维护，本服务不硬校验；
- 裁剪后工具数为 0 时，按「无工具」正常收尾，不报错。

## 4. 约束与依赖

- 权限码来自 `drone-server` 的 `permission` 表（如 `task:list`、`device:detail`）；
- 角色码：`admin` / `maintainer` / `pilot` / `screen`；
- 危险工具的角色限制已在 `agent.tool.role-tools` 配置中，本需求复用它。

# 规格 — REQ-AGENT-0019 Skill 资源纳入独立预算

- **需求 ID**：`REQ-AGENT-0019`
- **提出人 / 日期**：需求方 / 2026-10-23
- **负责人**：AI（按 SDD 执行）
- **前置**：`REQ-AGENT-0017`（上下文账单）、`REQ-AGENT-0018`（工具裁剪）

## 1. 背景与目标

`use_skill`（L2 正文）与 `read_skill_resource`（L3 资料）为了不被压坏，
被**完全豁免**了工具结果的单次与总量预算：

```java
private static final Set<String> UNCOMPRESSED_TOOLS =
        Set.of(UseSkillTool.NAME, ReadSkillResourceTool.NAME);
```

豁免的初衷是对的（曾把 12KB 的日报模板压成 10 个字），但代价是：

- 单次最多读 32,768 字符，**且不计入 6,000 字符的总量预算**；
- 一个请求里反复读多个资源，上下文可以无限增长；
- 账单能看到花了多少，但**没有任何上限**去阻止它。

目标：给 Skill 资源一个**独立预算**——既能保证模板完整可用，又有明确上限。

## 2. 范围

### 做（In Scope）

- 新增两个配置：
  - `agent.tool.max-skill-result-chars`：单次 Skill 资源上限（默认 32,768）；
  - `agent.tool.max-total-skill-chars`：一次请求内 Skill 资源累计上限（默认 30,000）。
- Skill 资源**不再走**通用 2,000/6,000 预算，也不再走模型摘要（模板不能被改写）；
- 超出预算时**硬截断并带明确标记**，告诉模型「后面还有内容、请分段读取」；
- 预算用尽时返回占位提示，而不是空串；
- 日志与账单反映实际加载量。

### 不做（Out of Scope）

- 不改 `agent.skill.max-body-chars` / `max-resource-chars`（文件级读取上限，保持不变）；
- 不做「按章节 / 行范围读取」的协议改造（需要改 Skill 工具入参，后续需求）；
- 不做 Skill 资源的向量检索或摘要；
- 不改通用工具结果的压缩策略。

## 3. 验收条件

| 编号 | 前置 | 操作 | 预期 |
|---|---|---|---|
| AC-1 | 日报 Skill 需要 12.3KB 模板 | 读取模板 | **完整返回**，内容长度不变、无截断标记 |
| AC-2 | 单次读取超过单次上限 | 读取 | 返回长度 ≤ 上限，末尾带「已截断」标记 |
| AC-3 | 一次请求内已累计 25,000 字符 | 再读 12,000 字符的资源 | 只返回剩余 5,000 字符 + 截断标记，**不超总量** |
| AC-4 | 总量已用尽 | 再读资源 | 返回「预算已用尽」占位，不返回空串 |
| AC-5 | 普通业务工具 | 读取长结果 | 仍按 2,000 / 6,000 预算压缩，行为不变 |
| AC-6 | 任意请求 | 查看日志与账单 | 日志显示 Skill 资料累计字符与截断次数；账单 token 与之一致 |

### 非功能要求

- 不触发额外的模型调用（Skill 资源**不做**模型摘要）；
- 截断按字符边界，不切断 UTF-16 代理对（避免半个 emoji）。

## 4. 约束与依赖

- 默认总量 30,000 的依据：日报正文 5.5KB + 模板 12.3KB + 口径 2.4KB ≈ 20KB，
  30,000 能容纳一次完整的日报流程，同时把最坏情况限制在约 1.5 万 token；
- 单次上限沿用 `agent.skill.max-resource-chars` 的 32,768（文件级已限制，工具层不再放宽）。

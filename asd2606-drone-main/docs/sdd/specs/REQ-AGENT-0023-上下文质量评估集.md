# 规格 — REQ-AGENT-0023 上下文质量评估集

- **需求 ID**：`REQ-AGENT-0023`
- **提出人 / 日期**：需求方 / 2026-10-23
- **负责人**：AI（按 SDD 执行）
- **前置**：`REQ-AGENT-0017`（账单）、`REQ-AGENT-0018`（工具裁剪）、`REQ-AGENT-0021`（按需记忆）、`REQ-AGENT-0022`（前缀稳定）

## 1. 背景与目标

前面的上下文改造（账单、裁剪、压缩、按需记忆、前缀稳定）都只有**单测与零散冒烟**，
没有一套可重复的「真实问题 → 指标」回归。改提示词、改工具、改预算后，只能靠人肉体验判断好坏。

目标：提供一套**手工可运行**的上下文质量评估集：

- 一组真实业务问题（含拒答、记忆、知识、统计）；
- 一次运行输出：通过率、工具选择、回答断言、延迟、上下文 token、缓存命中率、
  前缀指纹数、长期记忆注入次数；
- 结果为 Markdown 表格 + 可选 JSON，便于对比改造前后。

## 2. 范围

### 做（In Scope）

- `tools/context-eval/cases.json`：用例集（默认 9 条，日报等重用例需显式开启）；
- `tools/context-eval/run_eval.py`：登录 → 逐条请求 → 解析 agent 日志 → 汇总指标；
- 指标：通过率、工具命中/禁用、回答断言、平均/P95 延迟、上下文 token、累计 prompt、
  缓存命中率、前缀指纹数、长期记忆注入次数；
- 支持记忆夹具（`--memory-root`）：临时写入一段归档，跑完删除；
- 失败用例返回非 0 退出码（便于脚本化）。

### 不做（Out of Scope）

- 不做 LLM-as-judge 的语义评分；
- 不进 CI（会真实调用模型、产生费用、依赖运行中的数据）；
- 不覆盖多轮对话、流式接口、危险操作确认流程；
- 不评估向量检索（尚未实现）。

## 3. 验收条件

| AC-1 | 隔离实例 + 日志路径 | 运行脚本 | 输出逐用例表格与汇总 |

### 非功能要求

- 只依赖 Python 3 标准库；
- 不打印 token 与用户密码；
- 使用 `--memory-root` 时只写一个临时文件，跑完自动清理。

## 4. 约束与依赖

- 日志解析依赖 `【工具编排】` / `【上下文账单】` 的中文标记，改日志措辞需同步脚本；
- 缓存命中率受供应商 TTL 影响，跨轮次才有参考价值；
- 断言是关键词级，用于防回归，不替代人工评审。

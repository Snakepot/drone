# 规格 — REQ-AGENT-0021 长期记忆按需检索

- **需求 ID**：`REQ-AGENT-0021`
- **提出人 / 日期**：需求方 / 2026-10-23
- **负责人**：AI（按 SDD 执行）
- **前置**：`REQ-AGENT-0003`（长期记忆）、`REQ-AGENT-0017`（上下文账单）、`REQ-AGENT-0020`（会话内压缩）

## 1. 背景与目标

当前长期记忆**每轮无条件注入**其他会话的最近 10 轮 / 8,000 字符（`ContextAssembler`），
与当前问题无关也照付。实测账单里它是固定成本的一部分，且会稀释注意力。

目标：

1. **停掉无条件注入**（保留配置开关，可回滚）；
2. 新增 `search_memory` 工具，模型在需要时**按需检索**当前用户的历史会话原文；
3. 先做**关键词检索**（编号、人名、任务号是业务查询的主力）；
4. 删除语义保持天然正确：直接读归档文件，删会话即失效。

## 2. 范围

### 做（In Scope）

- `agent.memory.inject-enabled` 开关，默认 **false**（停掉无条件注入）；
- 新工具 `search_memory(query)`：只读**当前用户**的归档正文，关键词打分，返回最多 3 段原文摘录；
- 工具身份走显式 `ToolContext.userId`（执行器线程不读 ThreadLocal）；
- 系统提示词补充使用规则（提到「上次/之前/我说过」时先检索）；
- 账单不再出现「长期记忆」分类（除非回滚开启）；
- 日志：检索命中/未命中、耗时。

### 不做（Out of Scope）

- 不做向量检索（后续需求，工具契约不变；方向与门槛见 plan §7.2）；
- 不做用户画像（后续需求；设计要点见 plan §7.1）；
- 不做跨用户检索（永远只看自己）；
- 不改归档格式与删除逻辑。

## 3. 验收条件

| 编号 | 前置 | 操作 | 预期 |
|---|---|---|---|
| AC-1 | 默认配置 | 任意对话 | 上下文**不含**其他会话内容；账单无「长期记忆」 |
| AC-2 | 历史会话里有「TK-2026-1001 负责人是张伟」 | 问「上次 TK-2026-1001 的负责人是谁」 | 模型调用 `search_memory`，返回该段原文并据此回答 |
| AC-3 | 当前用户没有相关历史 | 检索 | 返回「没有找到相关记忆」，**不编造** |
| AC-4 | 用户 A 的历史 | 用户 B 检索 | 一条都查不到（只读自己目录） |
| AC-5 | 无用户身份（匿名/测试） | 调用工具 | fail-closed：返回「没有用户身份」，不读任何文件 |
| AC-6 | 回滚开关打开 | 对话 | 行为恢复为无条件注入（原逻辑） |

### 非功能要求

- 检索为本地文件扫描，单用户目录通常 < 几 MB；结果总长 ≤ 2,000 字符；
- 不打印消息正文到日志（只打命中条数与文件名）；
- 检索失败（文件不可读）返回失败结果，不抛异常拖垮对话。

## 4. 约束与依赖

- 归档正文格式由 `LongTermMemoryStore` 定义（段头 `## conv=… | 时间 | n 条`，消息一行一条、换行转义）；
- 工具元数据必须写进 `agent.tool.catalog`（`ToolRegistry` 启动校验 1:1）；
- 中文关键词不做分词：按整句、空白/标点切分、编号串三类匹配，语义召回留待向量方案。

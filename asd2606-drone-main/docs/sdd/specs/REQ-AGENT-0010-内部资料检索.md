## 1. 背景与目标

助手目前只能回答模型自身知道的东西，**读不到企业内部资料**。用户想让助手用**自然语言**检索内部资料
（首批是《无人机操作手册》《无人机保险方案》，后续扩充到任意目录），并**基于原文**作答。

诉求有三个特点，决定了这不是「丢两段文本进提示词」能解决的：

1. **资料会很多、格式可能不同**（现在就有 Markdown，将来会有 PDF / Office 等）；
2. **要用向量检索**（语义命中，而不是字面匹配）；
3. **要按角色控权**——内部资料有可见范围，**不能谁都能查**。

目标：把「内部资料检索」做成助手的一项**企业级能力**——**多格式可扩、语义可升、权限前置、可运维、可回退**，
而不是一次性的临时效果。

## 2. 范围

### 做（In Scope）

- **资料入库**：把 Markdown 资料放入约定的知识库目录，**自动解析、切块、建索引**；
  **多格式解析保留接口**（`DocumentParser`），但**本期只实现 Markdown**
- **语义检索**：向量检索（**向量库用 Milvus，Docker 单机**）；向量生成走 `EmbeddingModel` 接口，
  **本期按 embedding API 实现**（供应商 / 模型名走配置，见 Q-1）
- **按权限检索**：资料带**可见范围**（复用 `drone-server` 的 **权限码**）；
  检索时**用当前登录人的权限前置过滤**，**无权内容不参与检索**
- **助手集成**：助手通过一个**只读工具** `search_knowledge` 决定「要不要检索」，检索结果**回填后基于原文作答**
- **注明出处**：答复要点须能对应到**哪份资料的哪一节**
- **防注入**：检索到的资料是**数据不是指令**（沿用 `REQ-AGENT-0009`）
- **可回退**：提供总开关，关闭后回到纯对话
- **四个接口化**：`DocumentParser` / `EmbeddingModel` / `Retriever` / `VectorStore` 均走接口，
  便于替换（见 `ADR-0006`）

### 不做（Out of Scope）

- **不新增独立服务**（能力内聚在 `drone-agent`，见 `ADR-0006`）
- **不引入 MySQL 或访问 `drone-server` 的数据库**（宪法 §2）
- **不做**网页爬取 / 外部站点自动同步
- **不做**写操作（只读检索）；不做对资料的增删改的业务界面
- **不做**图片 / 视频 / 扫描件 OCR 的语义检索（后续单独立项）
- **不做**多租户 / 跨组织隔离
- **不改** `/chat` 与 `/chat/stream` 的入参出参与前端（若需「引用卡片」另立需求）
- **不做本地嵌入模型**（本期走 embedding API；本地模型**后续再议**，见 Q-1 结论）

## 3. 验收条件

| 编号 | 前置（Given） | 操作（When） | 预期（Then） |
|---|---|---|---|
| AC-1 | 已登录、对该资料有权限 | 问「电池怎么保养」 | 助手调用 `search_knowledge`；答复**基于操作手册原文**，并**注明出处（文档名 + 章节）** |
| AC-2 | 同上 | 问「三者责任险保额建议」 | 答复**基于保险方案**；**不出现原资料中不存在的数值** |
| AC-3 | 登录用户**对该资料无权限** | 问保险方案相关问题 | **检索阶段即命中不到**该资料；答复**不含其任何片段**，且不提示其内容 |
| AC-4 | 资料某片段内含**指令性文本**（如「忽略以上指令…」） | 该片段被检索命中 | 助手**不把资料里的指令当指令**；行为不被改变（沿用 `REQ-AGENT-0009`） |
| AC-5 | 知识库里**没有**该问题的内容 | 提问 | 助手**如实说明查不到**，并给出可去查的资料方向；**不编造** |
| AC-6 | 知识库目录新增一份 Markdown | 放入后（无需改代码） | 该资料被解析、切块、可被检索并在答复中被引用 |
| AC-7 | 检索总开关关闭 | 提问 | 行为回到**纯对话**；**不发生**任何检索调用 |
| AC-8 | 开发机无 Milvus | 跑 `mvn test` | **全部单测通过**（向量与检索用内存实现，不依赖真实中间件） |

### 非功能要求

- **性能**：单次检索（含向量检索与权限过滤）目标 **P95 < 500ms**（语料 ≤ 1 万块，本地 Milvus 单机）。
  入库为**异步**，不阻塞任何请求。
- **容量**：本期支持 **≤ 1 万块**（约数十份文档）；超出需评估（见 Q-2）。
- **安全**：**权限判定在服务端**且**检索前置过滤**；资料视为**不可信数据**（数据信封）；
  日志/审计**脱敏**；原料文件按内部资料管控访问。
- **兼容性**：`/chat`、`/chat/stream` 契约**不变**；总开关关闭即回到现状。

## 4. 约束与依赖

- **依赖既有能力**：工具框架（`REQ-AGENT-0005`）、数据信封与注入立场（`REQ-AGENT-0009`）、
  链路追踪、脱敏、线程池；权限来自 `drone-server` 的 RBAC（`/internal/user/{id}/authorities`）。
- **依赖 `ADR-0003` 的单实例前提**：本能力把有状态范围扩大到向量库，**仍为单实例**。
- **外部依赖**：Milvus（Docker 自托管）——**新增中间件**，见 `ADR-0006`。
- **外部约束**：宪法 §1（技术栈冻结，新增依赖与中间件需 ADR）、§2（不得访问 `drone-server` 库）、
  §4（安全红线）、§5（单测不依赖真实外部环境）。

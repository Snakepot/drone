# 规格 — REQ-AGENT-0031 Plan 模式（内置计划 + 生成计划）

- **需求 ID**：`REQ-AGENT-0031`
- **提出人 / 日期**：需求方 / 2026-10-27
- **负责人**：AI（按 SDD 执行）
- **前置**：`REQ-AGENT-0014`（Skill）、`REQ-AGENT-0029`（Harness）、`ADR-0012`
- **状态**：已实现；**功能未测试**（407 条单测 + 一次手工冒烟，尚未沉淀为可重复 E2E）

## 1. 背景与目标

当前 `drone-agent` 的编排只有 ReAct 循环：模型每一轮重新决定“下一步做什么”。
固定流程（日报）已经贴近 8 轮上限，可并行的步骤是否并行取决于模型；复杂任务也缺少
“先给用户看方案、批准后再执行”的能力。

目标：在现有 AgentLoop 上增加**可选的 Plan 模式**：

1. **内置计划（BUILTIN）**：固定强流程（如运营日报）严格按内置 JSON 计划执行，**不需要用户审批**；
2. **生成计划（GENERATED）**：复杂任务先生成计划，**必须展示给用户，用户批准后执行**；
3. 计划以 JSON 持久化，可查询、可审计；
4. 计划执行仍复用现有取消、预算、治理、幂等、台账能力；
5. 默认 ReAct 不变，Plan 是可选策略。

## 2. 范围

### 做（In Scope）

- `Plan` / `PlanStep` 数据模型与 JSON 格式；
- 内置计划目录 `resources/plans/*.json`，首个为运营日报；
- 内置计划执行器：依赖排序、只读步骤并发、写步骤串行、取消检查、`synthesize` 步骤；
- 生成计划：模型生成 JSON → 校验 → 落盘 → 返回待审批；
- 审批：用户批准后执行，拒绝则作废；同一计划最多执行一次；
- SSE/非流式响应携带计划摘要与步骤状态；
- 前端计划卡片（进度 / 批准 / 拒绝）。

### 不做（Out of Scope）

- 通用工作流 DSL / BPMN；
- 多 Agent 协作；
- 生成计划中途自动重规划（P2）；
- 危险工具在计划执行中自动放行（仍逐次确认；本期计划执行遇到危险工具直接拒绝）；
- 分布式计划存储（本期单实例文件）。

## 3. 审批语义（核心）

| 计划来源 | 是否展示 | 是否审批 | 执行 |
|---|---|---|---|
| **BUILTIN** | 展示步骤与进度 | **不审批** | 严格按内置 JSON 执行，不允许改步骤 |
| **GENERATED** | 展示完整计划 | **一律审批**，与只读/写无关 | 批准后执行；拒绝作废 |

补充：

- **危险工具确认独立存在**：计划批准 ≠ 危险操作批准；本期计划执行遇到危险工具直接失败并提示；
- 只读计划同样需要审批：只读也可能选错数据源、漏步骤、成本失控；
- 审批是计划级的“同意方案”，不是逐步骤审批。

### 3.1 非强制规则（明确记录）

Planner 提示词里的以下两条是**默认建议，不是强制验收条件**：

- “危险工具默认不主动引入”；
- “写操作以完成用户请求所必需为限，不额外扩大范围”。

真正的强制边界由运行时保证，**不靠提示词**：RBAC 权限、GENERATED 计划审批、
危险工具逐次确认、预算/限流。

当前 MVP 的执行器遇到危险工具会**直接拒绝该计划**，这是实现限制（避免绕过确认），
不是产品要求；后续接入“步骤级确认票据”后，可以允许计划包含危险工具并逐步确认。

## 4. 计划 JSON（示意）

```json
{
  "name": "daily-operations-report",
  "origin": "BUILTIN",
  "version": 1,
  "goal": "生成今日运营日报",
  "triggers": ["日报", "运营日报", "今天运营情况"],
  "steps": [
    {"id": "s1", "title": "总览", "kind": "TOOL", "tool": "drone__dashboard_summary",
     "args": {}, "dependsOn": []},
    {"id": "s2", "title": "今日任务", "kind": "TOOL", "tool": "drone__analytics_overview",
     "args": {"from": "${today.start}", "to": "${today.end}"}, "dependsOn": []},
    {"id": "s6", "title": "生成 HTML", "kind": "SYNTHESIZE",
     "skill": "daily-operations-report", "dependsOn": ["s1", "s2", "s3", "s4", "s5"]}
  ]
}
```

- `TOOL`：调用已注册工具；`args` 支持 `${today.start}`、`${today.end}`、`${s1.id}` 等引用；
- `SYNTHESIZE`：把步骤结果与 Skill 正文/模板交给模型生成最终答复；
- 生成计划由 Planner 产出同结构 JSON，`origin=GENERATED`，并带 `planId`。

## 5. 验收条件

| ID | 场景 | 期望 |
|---|---|---|
| AC-1 | 用户说“出个日报” | 命中内置计划，按 JSON 步骤执行，**不出现审批** |
| AC-2 | 内置计划某步失败 | 停在该步，如实报告，不继续后续步骤 |
| AC-3 | 复杂任务要求“先给方案” | 返回计划步骤，**不执行任何工具**，等待批准 |
| AC-4 | 用户拒绝生成计划 | 计划作废，不执行任何步骤 |
| AC-5 | 用户批准生成计划 | 按计划执行，返回结果与步骤状态 |
| AC-6 | 生成计划包含未注册/无权限工具 | 生成阶段拒绝，提示原因 |
| AC-7 | 计划 JSON 落盘 | 重启后可查询/审批（未过期） |
| AC-8 | 同一 planId 重复批准 | 只执行一次，第二次返回“已处理或已过期” |
| AC-9 | 计划执行中取消 | 后续步骤不再开始，返回已执行/未执行报告 |
| AC-10 | 普通 ReAct 请求 | 行为与改动前一致 |
| AC-11 | 计划执行包含危险工具 | 本期明确拒绝并提示，不绕过确认（MVP 临时限制，不是产品强制要求） |
| AC-12 | 只读生成计划 | 同样必须审批后才执行 |

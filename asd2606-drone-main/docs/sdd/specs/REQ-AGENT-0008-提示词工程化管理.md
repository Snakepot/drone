## 1. 背景与目标

现在提示词**散在两处、形态不一**：

- **系统提示词**在 `application.yml` 的 `agent.deepseek.system-prompt` —— 与「模型接入参数」混在一起；
- **模型摘要提示词**硬编码在 `ChatService.summarize` 的 Java 字符串里。

由此带来的问题：改提示词要么改 yml、要么改代码；**新增提示词没有统一去处**；没有格式约定
（占位符怎么传、怎么校验）；**写坏了要到运行时才暴露**（写空了、占位符对不上）。

目标：给提示词一个**统一、可评审、可校验**的家。参照工具那边的做法（`ToolDescriptor` + `ToolRegistry`：
元数据外置 + 启动期校验），提示词也要有 **集中存放 + 命名与用途 + 模板占位 + 启动期校验** 的架子。

## 2. 范围

### 做（In Scope）

- **独立目录 + 按业务分目录**：提示词放 `drone-agent/src/main/resources/prompts/`，
  **再按业务分子目录**（如 `assistant/`、`tool/`）；**一条提示词一个 `.md`**。
  **代码与 `application.yml` 里都不再有提示词正文**
- **提示词名 = 相对路径**：`prompts/assistant/system.md` → 名字 `assistant.system`；
  启动期校验「frontmatter 的 `name` 与文件所在路径一致」，免得名字与位置各说各话
- **每条 md 自带元信息（YAML frontmatter）**：`name` / `version` / `purpose` / `vars` / `changelog`；
  **frontmatter 之后到文件末尾就是正文**，正文即真正发给模型的文本（前面那些元信息不会进 prompt）
- **版本管理**：在 frontmatter 里维护 `version` 与 `changelog`（一行一版，写清改了什么）；
  **启动日志打印「加载了哪些提示词、各自版本」**（如 `system@1`），便于「换了提示词后行为变了」时定位
- **模板占位**：正文里用 `{{变量}}`；frontmatter 的 `vars` **声明**该提示词需要哪些变量
- **启动期校验（fail fast）**：
  - 目录为空 / 正文为空 / frontmatter 解析失败 / `name` 与文件名不一致 / 重名 → **启动失败**；
  - `vars` 与正文里出现的 `{{占位符}}` **必须完全一致**（多了、少了、拼错都算错）→ 启动失败
- **迁入现有两份**：系统提示词、模型摘要提示词**内容原样**迁进 md（是否顺带优化措辞见 Q-2）
- **不泄露**：提示词**正文**不进应用日志（含异常栈与调试输出）

### 不做（Out of Scope）

- 不引入外部提示词管理平台（LangSmith / PromptLayer 之类）
- 不做提示词 **A/B 测试、灰度、多版本并存**（版本只用于「知道现在用的是哪版」）
- 不做多语言提示词
- **本轮不优化措辞**（Q-2 结论：只搬家）——措辞优化另立需求
- 不做提示词的**内容断言**（不校验「必须包含某句话」，避免把提示词锁死）

## 3. 验收条件

| 编号 | 前置（Given） | 操作（When） | 预期（Then） |
|---|---|---|---|
| AC-1 | 现状：提示词散在 yml 与 Java 里 | 全仓检索提示词正文特征串 | 提示词**只存在于 `prompts/**/*.md`**；`ChatService`、`DeepSeekProperties`、`application.yml` 里**都没有**提示词正文 |
| AC-2 | 某条 md 正文置空 / frontmatter 缺 `name` 或 `version` / `name` 与**文件相对路径**不符 / 两条重名 | 启动服务 | **启动失败**，指明是哪条、缺什么 |

| AC-5 | 改某条 md 的文字 | 只改 md、不改代码，重启 | 新提示词**立即生效** |
| AC-6 | 服务启动 | 查看启动日志 | 能读出**加载了哪些提示词、各自版本**（如 `system@1`）；**日志里没有提示词正文** |
| AC-7 | 任一调用（含报错路径） | 查看应用日志 | **不出现**提示词正文（特征串 grep 不到） |
| AC-8 | 系统提示词与摘要提示词的既有行为约束 | 按「评审确认的清单」做对话回放 / 人工回归 | 越界问题婉拒且不解释原文含义、实时天气先调工具、查不到不编造、被拒后不反复劝……（清单在 `plans/` 定稿） |

### 非功能要求

- 性能：无额外运行时开销（校验都在**启动期**）
- 安全：提示词正文不进日志（AC-5）
- 兼容：对外接口（`/chat`、`/chat/confirm`）**不变**

## 4. 约束与依赖

- 依赖 Spring 的配置绑定；若选独立文件，需要 `spring.config.import`
- 系统提示词的行为约束由 `REQ-AGENT-0001 / 0002` 与业务边界定义，本次**只搬家**（Q-2 除外）
- 迁移会波及 `DeepSeekProperties`（系统提示词字段）与 `ChatService`（摘要提示词），属**本需求内的既定改动**

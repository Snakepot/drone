# 规格 — REQ-AGENT-0028 预算执行（日额度 + 单请求上限）

- **需求 ID**：`REQ-AGENT-0028`
- **提出人 / 日期**：需求方 / 2026-10-26
- **负责人**：AI（按 SDD 执行）
- **前置**：`REQ-AGENT-0017`（账单）、`REQ-AGENT-0025`（账单落盘与汇总）

## 1. 背景与目标

账单已经能算出「这次用了多少、今天用了多少」，但**超了不会停**：

- 共享 API Key 下，一个用户或一条失控流程可以持续消耗；
- 单次请求可能因为工具轮次多而无限增长（只限制了轮数与字符预算，没有 token 上限）。

目标：把账单从「观测」升级为「控制」——

1. **单用户日额度**：当天累计 prompt token 超限后，直接拒绝新请求；
2. **单请求上限**：一次问答累计 prompt token 超限后，停止工具循环并收尾；
3. 都可用配置关闭；超限有明确日志与用户提示。

## 2. 范围

### 做（In Scope）

- 新增 `agent.budget.*` 配置：开关、单请求上限、单用户日额度；
- `BudgetService`：
  - 日额度：读 `BillStore.aggregate(userId, today)` 的 `promptTokens`；
  - 单请求：读 `BillStore.summary(traceId)` 的累计 prompt；
- 入口拦截：`ConversationService` 的 `/chat` 与 `/chat/stream` 在调模型前检查日额度；
- 循环拦截：`ToolCallingService` 每轮模型调用后检查单请求上限，超限停止工具并返回预算话术；
- 日志：超限时打印 scope、已用、上限、userId/traceId。

### 不做（Out of Scope）

- 不做人民币计费与按模型定价；
- 不做管理员后台调整额度（先走配置）；
- 不做跨实例共享计数（依赖单实例账单文件）；
- 不按用户角色区分额度（后续可加）。

## 3. 验收条件

| 编号 | 前置 | 操作 | 预期 |
|---|---|---|---|
| AC-1 | 用户今日已用 ≥ 日额度 | 发 `/chat` | **不调用模型**；返回额度提示；日志有 WARN |
| AC-2 | 同上 | 发 `/chat/stream` | 不调用模型；`done.reply` 为额度提示 |
| AC-3 | 单请求累计超过上限 | 继续工具循环 | 停止提供工具并返回「已收尾」话术；不再调模型 |
| AC-4 | 未超限 | 正常对话 | 行为与改造前一致 |
| AC-5 | `agent.budget.enabled=false` | 超限场景 | 不拦截（回滚开关） |
| AC-6 | 账单关闭（无数据） | 任意请求 | 视为 0，不拦截（依赖关系显式记录） |
| AC-7 | 正常请求 | 查看账单/日志 | 预算判断不改变账单数值；超限有独立日志 |

### 非功能要求

- 预算判断只读账单，不额外调用模型；
- 日额度判断只读当天一个文件，开销可忽略；
- 超限提示不泄露内部提示词与工具细节；
- 失败（账单文件读不了）按「未超限」放行并 WARN——可用性优先。

## 4. 约束与依赖

- 预算依赖 `BillStore`；账单关闭时预算自动失效（配置说明里写清）；
- 单请求上限按「累计 prompt token」算（含每轮重发的工具定义），不是最终上下文大小；
- 单实例文件计数；多实例时需迁共享存储。

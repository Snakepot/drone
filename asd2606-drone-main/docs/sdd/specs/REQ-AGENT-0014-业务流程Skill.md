# 规格 — REQ-AGENT-0014 业务流程 Skill：标准化操作资产化

> 本文件只回答**做什么、达到什么效果**。实现方案见 `plans/`。

- **需求 ID**：`REQ-AGENT-0014`
- **提出人 / 日期**：需求方 / 2026-10-22
- **负责人**：AI（按 SDD 执行）

## 1. 背景与目标

助手已能通过 MCP 操作真实业务，但每次让模型「临场发挥」会导致步骤不稳、口径不一、经验无法沉淀。
目标：把可固定的业务流程做成 **Skill**（`SKILL.md` + 可选 `references/` 与 `assets/`），按**渐进式加载**进入上下文，
并按**用户权限裁剪可见性**，后续新增流程只加文件、不改代码。

## 2. 范围

### 做（In Scope）

- Skill 目录扫描与 L1 元数据目录；`use_skill`（L2 正文）与 `read_skill_resource`（L3 资源）两个工具。
- frontmatter 规定字段：`name/version/owner/description/when_to_use/permissions/tools`。
- **L1 按权限过滤**：用户具备 skill 声明的全部权限才可见、可用。
- 系统提示词 v7 注入「当前用户可见的 Skill 清单」。
- 首期四条流程：当日运营日报、派发前检查、告警分诊、飞手交接班；一个模板与一份口径资料。
- 启动校验：名字/正文/权限/工具引用；本地工具缺失即失败，MCP 工具缺失只告警。

### 不做（Out of Scope）

- 不做确定性工作流引擎（DSL 解释执行），本期是指令式 SOP（见 ADR-0009）。
- 不做在线编辑与热加载（改文件需重启）。
- 不做证据审计、航线巡检、周报等候选流程（仅登记）。
- 不新增业务接口。

## 3. 验收条件

| 编号 | 前置 | 操作 | 预期 |
|---|---|---|---|
| AC-1 | 四个 skill 已随包发布 | 启动服务 | L1 只含名称/描述/适用场景，不含正文 |
| AC-2 | admin / pilot / maintainer 三种账号 | 分别发起对话 | 系统提示词里可见 skill 数分别为 3 / 1 / 0（0 时显示「暂无」） |
| AC-3 | 用户有权限 | 调 `use_skill(daily-operations-report)` | 返回完整步骤与输出模板 |
| AC-4 | 用户无权限 / skill 不存在 | 调 `use_skill` | 两种情况返回**同一句**「没有找到该流程」，真实原因只进日志 |
| AC-5 | 已有 references | 调 `read_skill_resource` | 只允许 `references/` 与 `assets/`，拒绝 `..`/绝对路径/非白名单扩展名/超限大小 |
| AC-6 | admin 提问「出一下今天的运营日报」 | 走完对话 | 模型先 `use_skill`，再按固定步骤调用工具，输出固定版式日报 |
| AC-7 | 新增一个 skill 目录并放入合法 `SKILL.md` | 重启 | 无需改 Java 即生效（在权限允许的用户侧可见） |
| AC-8 | frontmatter 缺 `permissions` / 正文为空 / 重名 / 坏格式 | 启动 | 启动失败并指出具体 skill |
| AC-9 | skill 的 `tools` 引用了不存在的本地工具 | 启动 | 启动失败；若只是 `*__*`（MCP）未发现，则 WARN |

### 非功能要求

- L1：每个 skill 一行，≤ 60 tokens；按权限过滤后常驻成本随可见数量线性增长。
- L2：单个正文 ≤ 3000 字符；L3：单个资源 ≤ 32KB。
- 启动：不新增外部网络调用；扫描与解析 < 100ms（4 个 skill）。
- 安全：skill 可见性只是体验优化，**授权边界仍在 drone-server**；Skill 不绕过 RBAC。

## 4. 约束与依赖

- 依赖：现有 MCP 工具（`drone__*`）与本地工具框架。
- 与 prompts 一致：随包发布、启动校验、改文件需重启。
- 受控决策：指令式 SOP 的执行顺序由模型遵守，不由代码强制（ADR-0009）。

# 规格 — REQ-AGENT-0003 会话与长期记忆

- **提出人 / 日期**：项目负责人 / 2026-10-12

## 1. 背景与目标

`REQ-AGENT-0002` 交付的「简单记忆」是**前端每次回传全量历史、服务端无状态**。它带来三个问题：

1. **客户端可伪造轮次**（该需求登记的 Q-1），现有防线只能缓解、不能阻断。
2. **刷新即失忆、不跨设备**，长对话靠客户端反复回传全量历史。
3. 服务端对对话没有任何掌控，无法做记忆管理（检索、保留、删除）。

目标：**服务端持有会话状态**，提供会话级短期记忆与跨会话的长期记忆，
支持会话列表与删除。

## 2. 范围

### 做（In Scope）

- **会话级短期记忆**：服务端按 `userId + conversationId` 保存会话消息（内存，Caffeine 管容量与过期）
- **长期记忆落盘**：按 `用户分目录 + 按日期分文件`，并维护 `memory.md` 索引
- **落盘前脱敏**：敏感字段按规则脱敏后再落盘（见第 5 节）
- **过期即落盘**：会话空闲 **30 分钟**无访问 → 过期移除前写入长期记忆
- **停机兜底落盘**：服务优雅停机时，把内存中未落盘的会话写入长期记忆
- **按需加载**：启动只读索引；用户开始对话时读该用户的近期记忆；需要更早的再回溯
- **注入预算**：注入模型的记忆不超过**最近 10 轮 / 8000 字符**
- **会话列表**：服务端提供「我的会话列表」，**仅含当前用户自己的会话**
- **删除会话**：支持删除单个会话（**物理删除**长期文件中的该会话内容 + 记审计）
- **前端**：面板生成并保持 `conversationId`；提供「新建会话」按钮与会话列表

### 不做（Out of Scope）

- 不做多实例 / 分布式共享存储（ADR-0003 已明确放弃横向扩展）
- 不做多选批量删除（后续需求）
- 不做完整的记忆管理界面（只有会话列表 + 单会话删除）
- 不做记忆的导出 / 迁移能力（**本期明确不做**）
- 不做记忆的向量检索 / RAG
- 不做「按内容自动提炼长期记忆」的模型调用（长期记忆即**脱敏后**的原始消息）
- 不改单会话内既有的 20 条上限与角色白名单规则（沿用 `REQ-AGENT-0002`）

## 3. 验收条件

| 编号 | 前置（Given） | 操作（When） | 预期（Then） |
|---|---|---|---|
| AC-1 | 已登录且有权限 | 第一轮说「我负责华东区，机型 M300」；第二轮**只发问题**（不回传历史） | 回复正确引用「华东区」与「M300」 |
| AC-2 | 同一用户存在会话 A、B | 在 A 中告知机型 M300，在 B 中问「我的机型是什么」 | B 的回复**不含** M300 |
| AC-3 | 用户甲有会话 X | 用户乙用 X 的 `conversationId` 发请求 | 拒绝（403 或 404），**不泄露**甲的任何内容 |
| AC-4 | 活跃会话数已达上限 | 再发起新会话 | 最久未访问的会话被淘汰；其内容会被**异步归档**，归档失败进入重试队列 |
| AC-5 | 某用户有过会话且已落盘 | 服务重启后该用户再次对话 | 能读到重启前的记忆内容 |
| AC-6 | 某会话 30 分钟无访问 | 该会话被过期移除 | 长期记忆文件中出现该会话的记录 |
| AC-7 | 内存中有未落盘的活跃会话 | 服务**优雅停机** | 这些会话被写入长期记忆文件，无丢失 |
| AC-8 | 多次会话已落盘 | 检查存储目录 | 结构为 `<root>/<userId>/memory-YYYY-MM-DD.md`；`memory.md` 索引存在且每条记录能定位到文件 |
| AC-9 | 某用户单日记忆超过 2MB | 继续落盘 | 生成滚动文件（如 `memory-YYYY-MM-DD-2.md`），索引指向正确文件 |
| AC-10 | 某用户长期记忆远大于预算 | 发起对话 | 注入不超过最近 10 轮 / 8000 字符；超出部分**从最早处截断** |
| AC-11 | 长期记忆文件很多 | 服务启动 | **只读取索引**，不读全部正文（以读取文件数或启动耗时断言） |
| AC-12 | 某会话同时在内存与长期文件 | 用户删除该会话 | 内存移除；长期文件中**不再出现该会话的文本**；产生一条删除审计 |
| AC-13 | 同一文件内有会话 A、B | 删除 A | B 的内容完好无损 |
| AC-14 | 用户乙 | 尝试删除用户甲的会话 | 拒绝 |
| AC-15 | 打开助手面板 → 关闭 → 再打开 | 发消息 | 仍是**同一个** `conversationId`，上下文连续 |
| AC-16 | 点击「新建会话」 | 发消息 | 使用**新的** `conversationId`；模型上下文中**不含**上一会话的对话内容 |
| AC-17 | 某用户有若干会话、其他用户也有会话 | 获取会话列表 | 只返回**自己的**会话；不出现他人的任何会话 |
| AC-18 | 会话中含敏感字段（手机号、身份证、邮箱、密钥等） | 落盘后读取长期记忆 | 敏感字段**已按规则脱敏**；非敏感内容保持原文 |
| AC-19 | 某段会话含特定**非敏感**句子 X | 落盘后读取长期记忆 | 能以原文检索到 X |

> **关于 AC-16 与长期记忆**：新建会话只清空**会话内**上下文；该用户的**长期记忆仍然生效**
> （否则每次新建会话都等于失忆，长期记忆就白做了）。

> ✅ **AC-4 已修订（2026-10-13，批准）**：T-3 实测发现缓存的移除回调是**异步**执行的
> （跑在另一个线程上，调用方方法返回时尚未触发）。因此原措辞「淘汰时其内容**已成功落盘**」
> 这个保证给不出来——被淘汰与落盘之间存在时间窗，其间进程若终止则该会话内容丢失。
> 已按批准改为「淘汰后会被**异步归档**，归档失败进入重试队列」。

> 📌 **AC-5 的补充说明（2026-10-13，T-7 落地时）**：**恢复出来的是脱敏后的内容**。
> 正文落盘前已脱敏（AC-18），所以「能读到重启前的记忆内容」读到的是 `138****8000`
> 这类处理过的文本，不是原话。这是 AC-18（落盘必须脱敏）与 AC-5（能从盘上恢复）
> 叠加的必然结果，**不是缺陷**。它的实际影响是：跨重启的长对话里，
> 敏感字段的信息已不可逆地损失——模型看不到原号码。
> 此处只是把预期写明，**没有修改 AC-5 的要求**。

> 📌 **AC-14 的表现与字面不同（2026-10-13，T-13 落地时）**：AC-14 的字面预期是「拒绝」。
> 实际实现里会话键是「Token 里的 userId + conversationId」，**用户乙根本定位不到用户甲的会话**
> ——越权在结构上就不可能发生。但接口层面表现为「删了自己名下不存在的会话」，
> 按 DELETE 应当幂等，于是返回**成功**而不是报错。
> 也就是：**效果上等于拒绝（甲的数据分毫未动），返回码上不是拒绝**。
> 幂等是有意的——否则「重复点删除」「换台设备再删」都会报错。
> **留待确认**：接受这个口径，还是要求返回 404/403？

### 非功能要求

- **性能**：短期记忆按键读取，不得为 O(n) 扫描；长期记忆加载**不得在启动时全量读文件**。
- **容量**：内存短期记忆有明确上限（会话数 × 每会话条数）；磁盘按用户/日期分片，单文件 ≤ 2MB。
- **安全**：记忆严格按 `userId` 分区；**读取、列表、删除都必须校验归属**（宪法第 4 节）。
- **合规**：落盘前必须脱敏；永久保留（不自动过期），因此**删除能力是必要项**。
- **可靠性**：落盘**原子**（先写临时文件再改名），不留半截文件；
  落盘失败**不得阻塞淘汰**，但要记日志并可见。

### 约束与依赖

- 依赖 [`ADR-0003`](../decisions/ADR-0003-引入记忆与服务端有状态.md)：有状态、单实例、永久保留、用 Caffeine。
- 新增依赖 **Caffeine**（依赖评审已由 ADR-0003 完成）。
- 存储根目录：`agent.memory.root`，默认 `./data/agent-memory`。
  **部署必须挂卷**，否则容器重建即丢长期记忆；`data/` 已在 `.gitignore` 覆盖范围内。
- **破坏性契约变更**：请求体新增 `conversationId`；新增会话列表与删除接口。前端须同步。
- 本需求**推翻** `REQ-AGENT-0002` 的「服务端无状态」选择，该需求的 Q-1 随之关闭。

### 由上述决定推导出的两点与一项遗留（请确认）

1. **脱敏的代价**：既然要脱敏，长期记忆里就**检索不到敏感字段的原文**
   （如按完整手机号搜不到）。这与「存原文不丢信息」是有取舍的，本次取安全。
2. **刷新页面的行为**：规格未明确，我拟定为「前端记住当前会话 id，刷新后**恢复**该会话」——
   否则服务端有了长期记忆与会话列表，刷新却回到空白，体验是断的。**若不同意请指出。**
3. **遗留（不阻塞方案，但上线前需补）**：`ADR-0003` 未决第 6 条
   「承诺的容量增长预期 / 运维监控告警阈值」**未量化**。其余各项已澄清，此项留作上线前补齐。

## 5. 脱敏范围

落盘前必须处理的字段类别（具体规则与正则属实现细节，放方案里定）：

- 手机号
- 身份证号
- 邮箱地址
- 银行卡号
- 密钥 / 令牌（形如 `sk-`、`Bearer` 后的串）
- 密码类字段

> 要求：脱敏必须**可逆性为零**（不存原始值），但对非敏感内容**不得改动**（AC-19 即验证这点）。

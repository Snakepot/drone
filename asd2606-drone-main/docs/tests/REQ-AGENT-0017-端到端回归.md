## 一、系数标定（直连 DeepSeek）

用 `max_tokens=1` 的最小请求反推 `usage.prompt_tokens`：

| 样本 | 实测 | 推出系数 |
|---|---|---|
| 112 个汉字 | 73 token | 0.62 / 字（整段口径） |
| 131 个 ASCII 字符 | 28 token | 0.21 / 字符 |
| 每多一条消息（"a"） | +4 token | 每条 4 |
| 空对话固定开销 | 约 22 token | 模板 22 |
| 73 个工具定义序列化后 29,616 字符 | 约 10,490 token | **JSON 0.35 / 字符** |

> 最后一行的意义：JSON 的引号、冒号、英文键名几乎按字符计价，套自然语言系数会低估四成。
> 第一版就是漏了这条，账单整体偏差 −24%，补上 JSON 系数后收敛到 −1.5%～−2%。

## 二、流式账单（AC-1 / AC-2 / AC-3 / AC-4）

> 用户：「现在有多少设备？只回答数量。」

```text
【上下文账单】traceId=317d90ca，userId=5，conversationId=bill-smoke-3，
估算 12463 token（模板 22 / 系统提示词 1841×1 / 长期记忆 83×6 / 当前会话 13×1 /
工具调用请求 73×1 / 工具结果 69×1 / 工具定义 10362×73）；
工具结果分布 {drone__device_list=1}；
模型实际 prompt_tokens=12716，缓存命中=12544，估算偏差 -2.0%
```

- 每次模型调用一条，工具轮次各一条（该次请求共 2 条：请求工具那一轮 + 作答那一轮）；
- 分类齐全：系统 / 长期记忆 / 会话 / 工具调用 / 工具结果 / 工具定义；
- 工具结果带工具名（`drone__device_list`），能看出钱花在哪个工具上；
- 流式请求带 `stream_options.include_usage`，实际值来自最后一帧。

## 四、两个直接可用的结论

1. **工具定义占固定成本约 83%**（10362 / 12463），与改造前按字符测得的 88% 一致；
2. **前缀缓存命中率很高**：12544 / 12716 = 98.6%，说明系统提示词 + 工具定义这份稳定前缀
   被模型缓存住了；后续「按角色裁剪工具」会让这份前缀变小，缓存收益需要重新测量。
